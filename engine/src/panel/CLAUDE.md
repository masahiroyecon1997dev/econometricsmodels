## 実装済み（現状）

- `common.rs`: `PanelError`（FE/RE共有エラー型。`entity`/`time`の長さ不一致用`IdentifierDimensionMismatch`を追加）＋ `PanelDimension` enum ＋ `quasi_demean_column`（θパラメータ化した準偏差変換）。
- `fe.rs`: `FeInput`（入力データ型）。`y: Vec<f64>` / `x: Vec<Vec<f64>>` / `entity: Vec<String>` / `time: Option<Vec<String>>`等を保持する薄い入れ物で、`OlsInput`/`IvInput`と異なり`faer::Mat`は組み立てない（`quasi_demean_column`が列単位・`&[f64]`で動く設計のため、`fit()`実装が生の列をそのまま渡せる。詳細は`fe.rs`モジュールdoc）。`from_columns`は次元検証（`y`↔各`x`列・`y`↔`entity`・`y`↔`time`）と、`entity`/`time`の整数コード（`GroupCodes`）の構築のみ行う。
  - `within_transform_one_way`/`within_transform_two_way`（within変換）も実装済み。**2-wayは閉形式の二重デミーニング`ỹ_it = y_it - ȳ_i. - ȳ_.t + ȳ..`を直接計算せず、「entityでquasi-demean（θ=1）→ その結果をtimeでquasi-demean（θ=1）」という2段階の`quasi_demean_column`呼び出しで実装している**（バランスパネルでは数学的に閉形式と厳密に一致することを導出済み・rust-reviewerが独立検算のproptestで検証済み。導出は`fe.rs`モジュールdoc参照）。バランスパネル検証（`fe-spec.md`3.1節）は`validate_balanced_panel`（`fe.rs`内private）が担う: 単純な`n_obs == n_entities * n_periods`のカウント一致だけでは「あるペアの重複と別ペアの欠落が相殺する入力」を見逃すため、`(entity, time)`ペアが重複しないことも併せて検証する（`n_obs == n_entities * n_periods`のときだけ、グリッドのセルを`entity`コード×`n_periods`+`time`コードで一度ずつ埋めて重複を検出する。件数が合わなければ重複判定なしで即エラー。エンティティ数・時点数は`GroupCodes::n_groups()`）。`time`が未指定なら`PanelError::TwoWayRequiresTime`。
  - `validate_no_zero_variance_regressors`（分散ゼロ説明変数の検出、`fe-spec.md`1章）も実装済み。`within_transform_one_way`/`within_transform_two_way`どちらの出力にも使える1-way/2-way共通ロジックで、時間不変変数（1-way）・2-wayでtime FEと完全共線な「エンティティ間で変動しない列」を同じチェックで検出する。**閾値は絶対値ではなく相対値**（`.claude/rules/rust-style.md`「線形代数」の特異性判定の方針と同じ）: `column_is_zero_variance`（`fe.rs`内private）が、within変換後の列の標準偏差を「変換前の元の列の最大絶対値」×「観測数`n`」×`f64::EPSILON`と比較する。変換後の値自身をスケール基準にすると自己参照になり閾値が機能しなくなるため、変換前の値を基準にする（詳細な導出は`column_is_zero_variance`関数docコメント参照）。rust-reviewerレビュー済み（`assert_eq!`での列数・列長の内部契約チェック、n=0境界テストの追加を反映）。
  - `validate_no_singleton_groups_one_way`/`validate_no_singleton_groups_two_way`（singleton検出、`fe-spec.md`1章）も実装済み。**within変換の前に生の`entity`/`time`列を直接見る設計**（`within_transform_*`を呼ばない）——`fe-spec.md`1章が要求する「下流の特異行列エラーとして偶発的に検出される形にはしない」を満たすため。1-wayはentityのみ、2-wayはentity・time双方を対称に検出する。内部の`reject_singleton_group`（`fe.rs`内private）は`FeInput`のコード（`GroupCodes::counts`）を引き、観測順に走査して最初のsingletonを報告する。`validate_no_singleton_groups_two_way`は**`time`の存在チェックを最初に行う**（`within_transform_two_way`と同じ順序に揃える設計判断、rust-reviewer指摘を反映）——その後entity→timeの順でsingletonを検出する（両方該当時はentity側を報告、`FeInput`のフィールド順に合わせた恣意的な優先順位）。
  - `FeEffects`（`OneWay`/`TwoWay`）・`FeEstimator`（`OlsEstimator`への委譲、4.3節）も実装済み。`FeEstimator::fit`は`OlsInput::from_columns`を`include_intercept=false`固定で呼ぶ（Frisch-Waugh-Lovell定理によりwithin変換後のOLS点推定はFE推定量`β̂`と数学的に一致する）。`OlsEstimator::fit`自体は常に`cov_type=CovType::Classical`固定で呼ぶ（`β̂`・残差の取得のみが目的で、`cov_type`ごとの標準誤差はFE自身が独立に計算し直すため、委譲先のcov_type選択は結果に影響しないと確定した）。パイプラインは「singleton検出→within変換（2-wayはバランスパネル検証を内包）→自由度検証→分散ゼロ検出→`OlsEstimator::fit`への委譲→`cov_type`別の共分散行列計算→自由度調整後の統計量再計算」の順（`FeEstimator::fit`のdocコメント参照）。`OlsInput::from_columns`/`OlsEstimator::fit`が返す`LeastSquaresError`は`PanelError::WithinRegressionFailed { source }`に`.map_err`で明示的に包む（`common.rs`の方針、`#[from]`は使わない）。1-way/2-wayの切り替えは`FeEffects` enum（`bool`ではなく、`CovType`と同じ「小さな固定選択肢の公開enum」パターン、ユーザーとの相談で決定）を使う。将来`FEOptions`が導入されたら、その一部として統合される想定の暫定パラメータ。
  - **自由度調整（`fe-spec.md`3.2節）も実装済み**: `df_model = k + neffects`（1-wayは`neffects=n_entities`、2-wayは`neffects=n_entities+n_periods-1`。entity/timeダミー間の定数項ぶんの重複を`+1`補正）、`df_resid = n - df_model`。`n <= df_model`なら`PanelError::InsufficientDegreesOfFreedom`（この検証は`OlsEstimator::fit`自身の`n<=k`チェックより常に厳格——`neffects>=1`のため`df_model>k`が恒常的に成り立つ——なので、`FeEstimator::fit`経由でOLS側の`InsufficientObservations`が発生することは構造的にない）。t値・p値・信頼区間の自由度は`cov_type`によらず常に`df_resid`（3.3節、linearmodelsで確認）で、`crate::inference`の共有ヘルパー（OLS自身と同じロジック）から計算する。AIC/BICは`log_likelihood`自体は`SSR/n`のみに依存しdf非依存の式のため`OlsEstimator::log_likelihood()`をそのまま再利用し、ペナルティ項の乗数だけ`k`から`df_model`に差し替える。
  - **F統計量（`f_statistic`/`f_p_value`）も実装済み（当初は自由度調整の対応範囲外だったが、`panel-common.md`2.1節がOLS同様含める前提だったことがフィールド設計時に判明し前倒しで実装した）**: 傾き係数`k`個が同時にゼロという帰無仮説のWald F検定（`linearmodels.PanelOLS.f_statistic`「H0: All parameters ex. constant are zero」と同じ定義。固定効果ダミー自体は検定対象に含めない——`fixest`の`fitstat(m, "f")`はFEダミーも含めたモデル全体のF検定で定義が異なるためクロスチェックに使わない）。`crate::linear::ols::wald_f_test`（元々`OlsEstimator`本体・`wald_test_last_columns`が使う`fn`だったものを`pub(crate)`化）をFEの`cov_type`別`cov_params`・`df_resid`で呼ぶ形で再利用し、サンドイッチ計算を複製しない（`k_constant=0`固定、FEに切片は無いため）。**`estimator().f_statistic()`/`f_p_value()`は引き続き`df_resid_ols = n - k`・`CovType::Classical`ベースのままで誤り**（`FeEstimator`自身の`f_statistic()`/`f_p_value()`を使うこと）。失敗（共分散部分行列のほぼ特異性、`wald_f_test`のbackstop）は新設した`PanelError::FTestFailed { source }`（`WithinRegressionFailed`とは意味が異なるため別バリアント）。**この失敗経路のFE専用再現テストは意図的に見送っている**——`cov_type=Classical`である限り、委譲先の`OlsEstimator::fit`自身が同じ設計行列に対する同種のF検定を内部で無条件に計算しており、そちらが先に`WithinRegressionFailed`として失敗するため、OLSの`fit_returns_computation_failed_for_extreme_scale_difference_in_f_test`と同型の入力ではFE側の`FTestFailed`まで到達しない（実地確認済み。`wald_f_test`自体の正しさはOLS側のテストで担保される）。検証は`linearmodels`（`cov_type="unadjusted"`）の`f_statistic`と直接比較（`f_test_reference_input`、k=2の新規フィクスチャ、`FeCovType::Classical`のみ）に加え、`fixest::wald()`と全`cov_type`×1-way/2-wayで機械精度一致を確認している（`tests/panel/test_fe_crosscheck.py`、`run_fixest_benchmark.R`。**`wald()`は分母自由度を`max(df2, df1+1)`に切り上げるため、`G-1<=q`・`df_resid<=q`の境界（G=2、df_resid=1）ではp値が`summary`のt検定と食い違う。参照値のp値はfixestの統計量と`degrees_freedom(model,"t",vcov)`から`pf()`で計算し直している**）。k=1のケース（`fixest_reference_input`）は「1自由度のF検定は両側t検定と代数的に等価」という恒等式（`f_statistic = test_stat²`）で追加検証している——**この恒等式チェックは、rust-reviewerの指摘（初回実装ではClassical以外の`cov_type`でF統計量が一切検証されていなかった）を受けて、HC1/HC2/HC3/Cluster（no-rescale・with-rescale両方）/HACの既存k=1テストすべてに追加した**。これにより「`cov_type`別に計算し直した`cov_params`・`df_resid`が正しく`wald_f_test`に渡っているか」をcov_type横断で回帰ガードできる。
  - **検証の例外**: Python主リファレンスの`linearmodels`（`PanelOLS`）は`aic`・`bic`を一切提供しない（ソースコード確認済み。`rsquared_within`/`between`/`overall`/`inclusive`・`loglik`のみ）ため、この2つの検証はRクロスチェック（`fixest`）のみで行う（通常の「Python主リファレンス+Rクロスチェック」の2系統検証の例外、ハウスマン検定（5.3節）と同型）。上記の式は`fixest::feols`の`AIC()`/`BIC()`と数値的に一致することを実地検証済み（`fe_estimator_fit_one_way_matches_fixest_reference`/`_two_way_matches_fixest_reference`で固定）。
  - **パネル固有R²（2.3節）も実装済み**: `r_squared_within`/`r_squared_between`/`r_squared_overall`の3フィールド（`bareのadj_r_squared`は廃止、2.3節が明示的に要求）。素朴に「実際に使ったFE構造でdemeanしたR²」を3種とも定義すると考えがちだが、`linearmodels==7.0`のソース確認・実地数値検証で以下が判明している（ユーザーとの相談で決定、2026-09-12。詳細な式・導出は`fe.rs`モジュールdoc「パネル固有R²」）:
    1. **`r_squared_within`は「実際に使ったFE構造でdemeanした残差」を採用**（1-wayはentityのみ、2-wayはentity+time）——`estimator().r_squared()`をそのまま使う。**`linearmodels`自身の`rsquared_within`は常にentityのみのdemeanで固定**（2-wayモデルでも時間効果を含めない）という別定義のため、2-wayでは意図的に数値が食い違う。2-wayの検証はユーザー指示により`linearmodels`ではなく`fixest`の`fitstat(model, "wr2")`（"Within R2"）を使う（実地検証で1-way・2-way双方の数値一致を確認済み。AIC/BICと同型のRクロスチェック例外）。
    2. **`r_squared_between`/`r_squared_overall`は`linearmodels`の`_rsquared`と完全一致**させる。FEのxには定数列を含められない（含めれば`validate_no_zero_variance_regressors`が弾く）ため`has_constant=False`分岐（非中心化TSS）が常に適用される。`r_squared_overall`は固定効果の切片項を一切含めない元の`y`・`x`に`β̂`だけを当てはめた残差ベース（`estimator().residuals()`＝FWL定理による固定効果込みの残差とは別物）。`r_squared_between`はエンティティ平均`ȳ_i.`・`x̄_i.`に`β̂`を当てはめた残差ベース。
    3. **`r_squared_between`にエンティティ観測数`T_i`による重み付けをしてはいけない罠**: `linearmodels`の`_prepare_between`自体は不均衡パネル用の重み`w_i=T_i/mean(T)`を計算するが、`_rsquared`側でサンプルウェイト（`weights`引数）が全て`1.0`（未指定）なら`w`を無条件に`1.0`へ上書きする。**FEは`weights`引数をサポートしない**（CLAUDE.md 1.3節）ためこの重み付けは常に無効。一度`T_i`ベースの重み付き版を実装し、バランスパネルのテストでは`w_i=1`に退化するため気づかず、不均衡パネルで初めて`linearmodels`との数値不一致（0.9448 vs 0.9438）が発覚して修正した（`fe_estimator_fit_one_way_r_squared_between_matches_linearmodels_on_unbalanced_panel`で固定。バランスパネルのみのテストだと重み付けロジックの分岐が一度も実質的に検証されない典型例、DKバンド幅ループと同じ教訓）。
    - 新規ヘルパー（`fe.rs`内private）: `fe_r_squared_between`・`fe_r_squared_overall`（entity集計は`FeInput`のエンティティコードを使う）。
  - **`cov_type`対応（3.1節・3.2節）も実装済み**: `FeCovType` enum（`Classical`/`Hc1`/`Hc2`/`Hc3`/`Cluster{groups}`/`Dk{bandwidth}`）を`OlsEstimator`の`CovType`とは別に新設（HC0を含まない、無効な組み合わせを型で表現不可能にする設計）。**`OlsEstimator`の既存cov_type計算式（`classical_cov_params`/`hc_cov_params`/`cluster_cov_params`）はそのまま流用できない**——linearmodels/fixestのソース確認・実地数値検証で判明した3点の相違（詳細は`fe.rs`モジュールdoc「`cov_type`対応」）: Clusterの`G=2`の退化（`DegenerateClusterTwoGroups`）は下記「Driscoll-Kraay型パネルHAC対応」の「FEの2グループ退化」の項にDKとまとめて記載。
    1. HC0はスコープ外（linearmodels・fixestともにパネル/FE向けのHC0オプションが存在しない）。
    2. HC1〜HC3は独自計算: HC1は小標本補正係数が`n/(n-k)`ではなく`n/df_resid`。HC2/HC3のレバレッジは、within変換後の設計行列ではなくLSDV相当のフルレバレッジ`h_ii_full = 1/T_entity(i) + h_ii_within`（1-wayは分割回帰＝Frisch-Waugh-Lovellのレバレッジ分解則、2-wayはさらに`+ 1/N_time(i) - 1/n`）でなければならない（fixestと数値一致確認済み）。
    3. Clusterも独自計算（**linearmodels方式からfixest（R・Stata型）方式に変更済み**）: 補正係数はOLSと同じ`(G/(G-1))×((n-1)/(n-K))`だが、`K`はfixestの`ssc()`既定（`K.fixef="nonnested"`）に合わせたFE固有ロジック（`fe_cluster_k_correction`、`fixest:::ssc_compute_K`を実地検証して移植）で決める。linearmodelsの`n/(n-extra_df-k)`（`G/(G-1)`補正なし）とは一致しない。t検定・信頼区間・F検定の自由度も`G-1`に切り替える（fixestの`t.df="min"`）。詳細は`docs/spec/fe-spec.md`3.3節。
    - 新規ヘルパー（`fe.rs`内private）: `design_matrix_from_columns`（列→`faer::Mat`組み立て）・`xtx_inverse`（`(X̃'X̃)⁻¹`、`OlsEstimator`のprivateな`cov_params`を再利用できないため独立に計算し直す）・`leverage_within`/`leverage_full`・`fe_classical_cov_params`/`fe_hc_cov_params`/`fe_cluster_cov_params`・`fixef_dimension_nested_within_cluster`。
    - `cov_type`のデフォルト（`"cluster"`、entity単位、3.2節）・`cluster`文字列パースは`engine_pybind`層（`FEOptions`導入以降）の責務。`FeEstimator::fit`自体はデフォルトを持たない。
  - **Driscoll-Kraay型パネルHAC対応（3.1節）も実装済み**: `FeCovType::Dk { bandwidth: Option<i64> }`。着手時に`linearmodels.panel.covariance.DriscollKraay`のソースを実地確認し、以下をユーザー承認済み（2026-09-12、詳細な式・導出は`fe.rs`モジュールdoc「Driscoll-Kraay型パネルHAC対応」）:
    1. **カーネルはv1でBartlett限定**（OLSの`CovType::Hac`と平仄を合わせる）。Parzen/QSへの拡張は将来の拡張候補（未着手）。
    2. **バンド幅**は`linearmodels`のデフォルトルール`floor(4*(t/100)^(2/9))`（`t`=ユニークな時点数、OLSの`hac_lags`が観測数`n`ベースなのと違う点に注意）を`resolve_dk_bandwidth`で踏襲。明示指定は`[0, t)`範囲検証（`PanelError::InvalidDkBandwidth`）。
    3. **時系列順序は`time: Vec<String>`の辞書順とみなす**（`entity`と同じく同一性のみが意味を持つ列で順序情報を持たないため。ISO 8601日付・ゼロ埋め年度等、辞書順=時系列順になる形式で渡すことが呼び出し側の契約——`engine`側にこの契約のバリデーションは無い）。`panel_driscoll_kraay_cov_params`は`time`の`GroupCodes`（コードはキーの辞書順）で集計し、辞書順＝時系列順を一致させている。
    4. **1-way/2-way両対応**。2-way FEは`time`が既に必須だが、1-way FEで`FeCovType::Dk`を指定したのに`time`が`None`なら`PanelError::DkRequiresTime`。
    5. スケールは`(t_periods/(t_periods-1)) × ((n-1)/(n-K)) × (X̃'X̃)⁻¹ Ŝ (X̃'X̃)⁻¹`（**linearmodels方式（`n/df_resid`）からfixestの`vcov="DK"`（`ssc()`既定）方式に変更済み**）。`K`はDKにクラスター変数が無くネスト判定が発生しないため常に`K=df_model`（`K.fixef="full"`）。t検定等の自由度は`t_periods-1`。カーネル本体（Bartlett重み・ラグ項の積算）とバンド幅の既定式は`linearmodels`のDriscollKraayのソース確認に基づくまま。
    - **回帰テストとしての交差検証**: `bandwidth=Some(0)`（ラグ項なし）は`FeCovType::Cluster { groups: Some(time) }`（entityと無関係なクラスター変数。`fe_cluster_k_correction`でどのFE次元もネストしないため`K=df_model`、DKも`K=df_model`）と数式的に同一になるため、2つの独立実装（`panel_cluster_cov_params`/`panel_driscoll_kraay_cov_params`）の一致を確認するテストを追加している（OLSの`fit_hac_with_zero_lags_matches_hc0`と同型の手法）。
    - **`FeCovType::Dk.time`による時系列順序の明示的な上書き**: `Dk { bandwidth: Option<i64>, time: Option<Vec<String>> }`に拡張した（元は`bandwidth`のみ）。`engine_pybind`のFEOptions設計時に「2-way FEの`time`（固定効果構造）とDK HACの時系列順序を別の列にしたい」というユースケースが判明したため（ユーザー承認済み、2026-09-12）。`time`が`Some`なら`input.time()`より優先してDK計算に使う（`FeInput.time()`が`None`の1-way FEでもこれだけでDK HACが成立する）。`FeInput`自体は変更していない——`time`はcov_type固有のオプションであり、パネル構造（2-wayの有無）とは独立に指定できる設計。
    - **FEの2グループ退化（`DegenerateDkTwoPeriods`/`DegenerateClusterTwoGroups`）**: FEのDKで`t_periods=2`、またはClusterで`G=2`（2時点のパネルを`time`でクラスタリング等）のとき、全エンティティが2グループに1観測ずつだとwithin変換で各エンティティの2観測が符号反転（`x̃_i1=-x̃_i2`・`ẽ_i1=-ẽ_i2`）し、グループスコアが等しく和がゼロ→恒等的にゼロ。`t > q`/`G > q`は`k=1`で通ってしまい、`1×1`行列は`ensure_well_conditioned_symmetric_matrix`の相対閾値でも検出できないため、SE≈1e-16・F≈1e30を黙って返していた（実測）。`two_group_split_is_degenerate`（`fe.rs`）で`k >= 1`のときだけ事前に弾く。**2-wayではtime方向も同じ構造**（within変換はtimeの水準内でも和をゼロにする）: エンティティ2つの2-way FEをentityでクラスタリング（Clusterの既定）すると全時点が2クラスターに1観測ずつになり同じく退化する（rust-reviewerが実測: SE≈1.7e-16）。entity方向だけ見る判定だとこれを取りこぼす。1エンティティでもパターンが崩れれば（同じグループに2観測等）退化しないので通す（その場合のSEは有限だが少数のエンティティに依存し不安定）。REは残差がwithin変換されないため対象外（ハウスマンの補助回帰も同様、Clusterは`G > 2k`で`G=2`自体が通らない）。 `Dk.time`の上書き列は`FeInput`の検証を通らないため、DKアームの先頭で長さを検証する（`IdentifierDimensionMismatch`、Clusterの`validate_cluster_groups`と同じ水準。退化判定の`zip`切り詰め・DK計算の範囲外アクセスを防ぐ）。

    - **実装はFEと同じ`wald_f_test`を、RE自身の`cov_type`別`cov_params`・`df_inference`で呼ぶ形**（`k_constant=1`: 先頭列が変換済み定数項、検定対象は傾き`df_model - 1`個。サンドイッチ計算を複製しない）。**RE自身の`cov_type`に連動する**（ユーザー判断でFEと揃えた。最初は`estimator().wald_test_last_columns`で古典共分散・`df_resid`固定にしていたが、`estimator()`の`cov_params`は`CovType::Classical`のためRE自身の`cov_type`を反映できず、ロバスト検定にならないため変更）。`f_df()`の分母自由度は`df_inference`（`Cluster`で`G-1`・`Dk`で`t_periods-1`・それ以外は`df_resid`）で`stat_df`と常に一致する。失敗は`PanelError::FTestFailed { source }`（FEと共用）。この失敗経路の専用再現テストは未作成（FEの`FTestFailed`が`OlsEstimator::fit`側の同種のF検定に先に阻まれて到達しにくいのと同型の可能性が高いが、REでは確認していない）。傾き係数が0個（`df_model==1`）ならOLS/FE同様NaN。
    - **`linearmodels`のSST/SSR方式から変更した経緯と理由（設計判断）**: 当初は`linearmodels.RandomEffects.fit().f_statistic`に数値一致する定義（変換済みyの単純平均を基準にした古典的SST/SSR比較）を直接実装していた。`linearmodels`の`_PanelModelBase._f_statistic`は「定数項を除く」際の比較対象（`weps_const`）を、実際にモデルに含まれる変換済み定数列（`1-θ_i`、エンティティごとに異なる）ではなく**変換済みyの単純平均**（`y - mean(y)`）で計算しており、教科書的な入れ子モデル比較（`total_ss >= residual_ss`保証）とは異なる。そのため**極端に不均衡なパネル（`T_i`の差が大きい、T_i={2,2,15}等）で負値になる**。`plm:::pwaldtest`はWald二次形式（`V`が正定値なら負値にならない）のためこちらに変更した（ユーザー判断）。主リファレンス全体を`plm`に切り替えるのではなく、`f_statistic`/`f_p_value`の1統計量だけが対象（他の統計量は`linearmodels`と数値完全一致で検証済み）。
    - **`linearmodels`との比較は`f_statistic_robust`（`cov_type`連動のWald二次形式）を使う**: classical/hc1ともに不均衡パネルでも機械精度で一致する（点推定が一致するため）。`res.f_statistic`（SST/SSR方式）はバランスパネルのclassicalでは一致するが、不均衡パネルでは一致しない（`θ`が全エンティティ共通でなく変換済み定数列が全観測で同一の値にならないため）ので使わない。`plm`の`pwaldtest(test="F", vcov=...)`の統計量とはバランスパネルで全`cov_type`（hc2/hc3/cluster/dk）が機械精度で一致する。
    - **不均衡パネルの`plm`との差**: Swamy-Arora分散成分の推定差（`θ`の差）により`cov_type`別に最大 hc2 8.7e-4・hc3 8.5e-4・cluster 1.3e-3・dk 6.7e-3（相対、classicalのみ別途3e-4）。許容誤差は`tests/_tolerances.py`の`re_crosscheck.rtol_unbalanced_f`（cov_type別）。**`plm`のp値は使わない**: `pwaldtest`の分母自由度は`vcov`の種類で決まり本実装の規約と一致する保証がないため、参照値のp値はplmの統計量とt検定と同じ分母自由度から`pf()`で計算し直している。**`plm`・`linearmodels`ともにこの差はF統計量だけでなく係数にも出る既知の差**（`docs/guide/verification.md`参照）で、F統計量固有のバグではない。
    - 検証: エンジン単体テストは、傾き係数が1個のデータで`f_statistic = test_stat²`・`f_p_value = p_value`（1自由度のF検定と両側t検定の代数的等価）を全`cov_type`で固定し（`re_estimator_fit_f_statistic_follows_cov_type_and_matches_squared_t_statistic`、極端な不均衡の`re_estimator_fit_f_statistic_is_wald_form_for_extremely_unbalanced_panel`）、`plm`との数値照合は`tests/panel/test_re_crosscheck.py`（`run_plm_benchmark.R`が`pwaldtest(vcov=vc)`の統計量を出力）で行う。
  - **パネル固有R²（`ReEstimator::r_squared_within()`/`r_squared_between()`/`r_squared_overall()`、2.3節）も実装済み**: FEの`fe_r_squared_between`/`fe_r_squared_overall`をそのまま流用できない・共有せずRE独自の`re_r_squared_within`/`re_r_squared_between`/`re_r_squared_overall`として実装した（`docs/spec/re-spec.md`3.6節「無理な共通化はしない」）。差異は2点:
    - **TSSの中心化有無**: REは`has_constant=True`のため中心化TSS（`Σ(y-ȳ)²`）を使うが、FEは`has_constant=False`扱いのため非中心化TSS（`Σy²`）を使う（`weights`引数はFE/REどちらも未サポートのため常に`w=1`——`_prepare_between`の`T_i`ベース重み付けはFE同様常に無効、`fe_r_squared_between`関数doc参照）。
    - **当てはめ値への切片`β0`の有無**: FEは固定効果自体を含めない「弱いR²」を意図的に採用する（`slope_only_residual`）が、REは真の切片係数`β0`（`params().get(0,0)`）を含めて当てはめる（`fitted = β0 + Σ_j x_j・β_j`）。単なる`has_intercept`分岐の追加では済まず、フィット済みの値そのものの計算式が変わるため共有関数化を見送った。
    - `r_squared_within`はFEと同じ定義（θ=1固定の通常のwithin変換、REの`θ_i`とは無関係）。**within変換済みの`y`・`x`は`swamy_arora_variance_components`が返す内部1-way FE推定の`fe.estimator().input()`（切片なしの`Mat`）を再利用し、`re_r_squared_within`では変換し直さない**（ハウスマン検定の`X̃`も同じ）。同じ`y`・`x`・`entity`に`within_transform_one_way`を適用済みのためビット単位で同値（`re_estimator_fit_r_squared_within_matches_fresh_within_transform_exactly`・`re_estimator_fit_hausman_matches_fresh_within_transform_exactly`で固定、前提は`debug_assert_within_reuse_contract`でdebugビルド時に確認）。整数コード化（下記「整数コード（`GroupCodes`）」）の前は、n=1,000,000・k=5でwithin変換1回が約1秒（`quasi_demean_column`が列ごとにエンティティ文字列をハッシュし直していた）で、R²とハウスマンでそれぞれ変換し直していた分（計約2秒、RE全体の約4割）を削った。
    - `linearmodels`の`_rsquared`の早期リターン（`has_constant and exog.nvar==1`なら3種とも`0.0`）に倣い、`df_model==1`（傾き係数0個）なら3種とも`0.0`とする（`f_statistic`のNaN分岐とは異なる扱い）。
    - `r_squared_between`が負値になりうる（`linearmodels`のSST/SSR方式のF統計量と同型の性質、教科書的な保証が無いR²の定義のため。F統計量自体はWald形式に変更済みで負値にならない）ことも実地確認済み（`re_estimator_fit_matches_linearmodels_reference`でRE Between R²=-0.39...を固定）。

## 設計上の決定（再発見コスト削減）

- **`engine` はpolars非依存。`panel-common.md` `fe-spec.md`3.1節の「polarsの`group_by`で実装」は`engine_pybind`層／抽出後配列の話**。`engine`側のグループ集約は、クラスター列と同じく `entity: &[String]`（長さ`n`、行はパネル観測順）を受け取る。
- **整数コード（`GroupCodes`、`common.rs`）**: entity・time・クラスター列は`FeInput`/`ReInput`の構築時（クラスター/DKの明示指定列は`fit()`の該当アーム）に一度だけ整数コードへ変換し、within変換・準偏差変換・エンティティ平均/R²・θ計算・singleton/件数チェック・cluster/DKの集計はコードで配列を直接引く。以前は`String`キーの`HashMap`/`BTreeMap`を列ごと・統計量ごとに引き直しており、n=1,000,000（エンティティ166,666）で1列約0.2秒、FE/REの計算時間の大半を占めていた（QR分解よりはるかに重い）。コード化後はn=1,000,000・k=5でRE約4秒→約0.9秒、FE約1.5秒→約0.25秒（ローカルのA/B計測）。
  - **コードはキーの辞書順に振る**（`String`の`Ord`＝旧`BTreeMap`の反復順）。グループ間加算の順（クラスターの`Σ_g S_g S_g'`）・between回帰の行順・DKの時点順（辞書順＝時系列順の規約）を旧実装と同じに保つため。グループ内の行は観測順（`group_indices`は安定な計数ソート）。**結果は旧実装とビット単位で一致**（FE 1-way/2-way・RE×全cov_type・fixed_effects・singletonエラーの47構成で全統計量のビットを比較して確認済み）。グループ間加算があるパネル系の実装を今後書くときも、このコード順（＝`BTreeMap`順）で回すこと。
  - RE本体の内部FE（分散成分推定）は`FeInput::from_re_input`で`ReInput`のコードごと作り、作り直さない（文字列とコードを別引数で受けないので食い違う余地が無い）。
  - HC2/HC3のレバレッジ補正（`leverage_full`、グループサイズは`counts()`）・クラスターのネスト判定（`fe_cluster_k_correction`/`fixef_dimension_nested_within_cluster`、水準→クラスターコードの対応配列）・2グループ退化判定（`two_group_split_is_degenerate`）・ハウスマン補助回帰のclusterもコードで引く。
  - 2-wayのバランス検証（`validate_balanced_panel`）・`fixed_effects()`（`group_residual_means`、キーの`String`は出力時に`keys()`から作る）もコードで引く。`fit`/`fixed_effects()`の内部にはもう`String`キーのグループ化は残っていない（`FeInput`/`ReInput`が構築時に生の`entity`/`time`文字列をコードと別に保持しているのは残り、`entity()`/`time()` getterがその読み手）。
- **`quasi_demean_column` は列単位の関数**（`y`/`x`をまとめて受けない）。呼び出し側（FE/REの`fit()`）が `y` と `x` の各列にループ適用し、変換後の列を `OlsEstimator::fit` に渡す（WLSがsqrt(w)変換データをOLSへ委譲するのと同型、4.3節・`re-spec.md`3.2節）。列ごとに独立な変換のため単体テストが単純になる。
- **θはエンティティコード順の`&[f64]`（長さ`n_groups`）で渡す**（`quasi_demean_column(col, &GroupCodes, &[f64])`）。当初は「順序規約をFE/REで共有する必要が生じミスの余地が残る」ため`&BTreeMap<String, f64>`（エンティティID→θ_i）にしていたが、整数コード化で順序規約が`GroupCodes`1か所に閉じた（θは同じ`GroupCodes`のコードで引く）ため置き換えた。`quasi_demean_column`はPythonから呼べない（`engine_pybind`も使わない）ため、互換ラッパーは残さず`GroupCodes`ともども`pub(crate)`にした。**FEはこの関数の `θ_i = 1.0`（全エンティティ）の特殊ケース**として扱う（`panel-common.md` `re-spec.md`3.2節）。REは `θ_i = 1 - sqrt(σ_ε² / (T_i·σ_u² + σ_ε²))`（`re-spec.md`3.2節）。
- **`quasi_demean_column` はグループ平均（`ȳ_i.`）を返さない**（設計上のスコープ外）。**`fixed_effects()`（`fe-spec.md`3.5節）はこの関数を拡張せず実装済み**——`FeEstimator::fixed_effects()`は`fit()`が既に保持している`input`（変換前の元の`y`/`x`/`entity`/`time`）と`estimator().params()`から`slope_only_residual`/`group_residual_means`で都度再計算する（`quasi_demean_column`はwithin変換専用のまま据え置き）。σ_ε²再利用（`re-spec.md`3.2節、RE実装）で平均の保持が必要になったら、その時点で改めて検討する。
- **契約違反（`entity`と列の長さ不一致・`theta`の長さがグループ数と不一致）は`assert!`/`expect`でpanic**（`Result`を返さない）。ユーザー入力起因ではなく`engine_pybind`〜`engine`間の内部契約違反のため、`validate_cluster_groups`の`assert_eq!`と同じ扱い。`hausman_statistic`のshape契約（`beta_fe`/`beta_re`同長・`cov`が`k×k`）も同様に`assert!`。


## 踏んだ罠: between回帰でエンティティ平均が完全に一致すると`OlsEstimator::fit`が`StudentsT::cdf(NaN)`でパニックする（パネル固有R²の実装時に発見した、その対応範囲外の既存バグ）

- パネル固有R²（`re_r_squared_between`）のテスト作成中に発見した。**`swamy_arora_variance_components`のbetween回帰（`OlsEstimator::fit`）と`re_r_squared_between`は無関係だが、同じデータ条件（全エンティティの`ȳ_i.`が完全に一致）で同時に踏む**——REのbetween R²のTSSが0になる条件（`Σ(ȳ_i.-grand_mean)²=0`）は、between回帰自身が「切片=共通の平均値・傾き=0」という完全な当てはめ（`SSR_between=0`）になる条件と全く同じであるため。
- `SSR_between=0`だと`classical_cov_params`の`σ²=0`となり、between回帰の**全係数**の`std_error=0`になる。もし共通の平均値自体も0（＝切片の係数も0）なら、`OlsEstimator::fit`内の`compute_inference_stat`（`crate::inference.rs`）が`stat = coef/se = 0.0/0.0 = NaN`を計算し、続く`dist.cdf(stat.abs())`（`StudentsT::cdf`）が`statrs`の`beta_reg`内部で`XOutOfRange`としてパニックする。
- **【修正済み】`crate::inference::compute_inference_stat`はこのNaN t統計量をガード済み**: `stat.is_nan()`のとき`dist.cdf(...)`を呼ばず`p_value`もNaNとして返す（panicではなく、統計的に不定であることをそのまま伝える）。OLS/WLS/FE/RE/Logit/Probit/Tobit/2SLS/GMMなど`compute_inference_stat`を経由する全手法に共通して適用される（`engine/src/inference.rs`の`compute_inference_stat_returns_nan_p_value_without_panicking_when_coef_and_se_are_both_zero`で固定）。
  - **本節のデータ（全エンティティ平均が0で一致）で`swamy_arora_variance_components`を実際に呼ぶと、修正後はNaN t統計量のガードは通過するが、その先の`wald_f_test`（`OlsEstimator::fit`が常に計算するF統計量。`cov_params`がσ²=0で全体ゼロ行列になるため、傾き係数の共分散部分行列がゼロ行列＝非正定値）が`ensure_well_conditioned_symmetric_matrix`で`CommonError::ComputationFailed`を返し、`PanelError::BetweenRegressionFailed`として伝播する（`Ok`にはならない）。パニックせずエラーとして伝播することがこの修正の目的であり、Err自体は`swamy_arora_variance_components`がF統計量を使わなくても`OlsEstimator::fit`が常にF検定を計算する既存の構造的な帰結（この修正のスコープ外）**。実地確認・回帰ガードは`swamy_arora_variance_components_does_not_panic_when_entity_means_are_all_zero`。
  - `k=0`の構造的退化を扱う既存の別問題とはトリガー条件・原因のクレート（`statrs`対`faer`）が異なる。**【対応済み】** 当初`OlsEstimator::fit`にk=0拒否ガードを追加しようとしたところ、FE/REが内部で`OlsEstimator::fit`にk=0（固定効果のみモデル）を渡す既存仕様と衝突することが判明し一時中断した。「FE: xの空リスト許容の見直し」の対応（`engine_pybind`層でFEのx=[]を拒否）実装後も、**engine層（`FeInput::from_columns`・`FeEstimator::fit`）は引き続きk=0を受理する設計を維持しており**（`fe_estimator_fit_with_no_regressors_estimates_fixed_effects_only_model`で固定）、この衝突自体は解消していなかった。最終的に`OlsEstimator::fit`（公開、k=0を`CommonError::NoRegressors`で拒否）と`pub(crate) fn OlsEstimator::fit_allowing_no_regressors`（同じ実装、このガードのみスキップ）に分割し、`FeEstimator::fit`だけを後者の呼び出しに切り替える形で解決した（`engine/src/linear/CLAUDE.md`「k=0の扱い」参照）。RE自身の2つの`OlsEstimator::fit`呼び出し（between回帰・最終回帰）はどちらも構造的にk=0にならない（常に切片または準偏差変換した定数列を最低1列持つ）ため無変更のまま——FE側の変更だけで`swamy_arora_variance_components`経由の間接呼び出しも連鎖的に解決する。
- **回避策（`re_r_squared_between`のテストで採用）**: エンティティ平均を「全て同じ非ゼロ値」にすると、切片の係数自体は非ゼロになり`t統計量=非ゼロ/0=±∞`（`NaN`ではない）になるためこのパニックを回避できる（`statrs`は無限大の`t統計量`自体は正しく処理できる。`re_estimator_fit_r_squared_between_returns_zero_when_entity_means_are_equal`参照）。REのbetween R²のTSSはyの水準シフトに対して不変（中心化TSSのため）なので、この回避策でもテストしたい退化条件（TSS=0）自体は変わらない。
- 今後、between回帰・その他の回帰で「エンティティ（またはグループ）平均が完全に一致する」ような退化データをテストで構成する際は、この罠に注意すること（同じ理由で対称的に踏む）。

## PanelError（確定済みの方針、変更時は要確認）

- FE/REで共有（`FeError`/`ReError`は作らない）。`CommonError` を `#[error(transparent)] Common(#[from] CommonError)` で包む（`LeastSquaresError`/`MleError`/`IvError` と同じ）。
- `WithinRegressionFailed { #[source] source: LeastSquaresError }` は `#[from]` を使わず明示的に `.map_err` で包む（`CommonError` が2経路で `PanelError` になる曖昧さを避けるため。`IvError::FirstStageFailed` と同じ判断）。`FTestFailed { #[source] source: LeastSquaresError }`も同じ`LeastSquaresError`ラップだが、`OlsEstimator::fit`委譲の失敗ではなくFE独自のF検定（`wald_f_test`再利用）の失敗を表すため別バリアントにしている。
- RE固有バリアント（between回帰の自由度不足等）は未定義。RE実装issueで計算コードを書く過程で追加する（`common.rs` モジュールdocコメントの「追加候補」参照）。

## property-basedテスト（`mod proptests`）

- FE（`fe.rs`）は`fit`レベルで「yへのentity/time定数加算」「行並べ替え＋entityラベル付け替え」「yスケール線形性」「LSDVオラクル（傾き・Classical SE）」を検証する。REは「θの値域`[0,1)`」「`σ_u²=0`でpooled OLSと一致」「行並べ替え＋ラベル付け替え」（ハウスマン統計量も含む）。ケース生成器はFE/REで別定義（FEは2-wayのためバランスパネル、REは不均衡パネル固定）。
- **`quasi_demean_column`はFE・REの両方の土台**なので、バグ注入は`common.rs`側で行うと両方のプロパティを検証できる。ただし`y=Σx+ノイズ`のDGPでは「グループ平均を定数倍ずらす」ような注入は`y`と`x`で相殺して二次効果に埋もれ、LSDV/行順序系プロパティでは検出できない。注入は「観測単位で値を汚す」（`n>20`かつ値>5のときだけ+1e-3等）か「行順序依存にする」（グループのk番目の観測を和から除く）形にする。
- `σ_u²=0`でのpooled OLS一致は、entity効果なしのDGPだとSwamy-Arora推定量の`max(0)`により約半数のケースで自然に成立するため、`prop_assume!(sigma2_u == 0.0)`で棄却しても`too many rejects`にならない。
