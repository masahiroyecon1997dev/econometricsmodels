# engine/src/panel/ 実装ノート（FE/RE/FEIV）

このファイルは `engine/src/panel/` 配下のファイルを読み書きするときだけ自動ロードされる。設計の背景・数式の正本は `docs/spec/fe-spec.md` / `docs/spec/re-spec.md`（FE/RE共通の論点は `docs/spec/panel-common.md`）、定義式は `docs/methods/fe.md` / `re.md`。各部品の契約は `fe.rs` / `re.rs` のモジュールdocにある。ここに書くのは「削除するとClaudeが同じ判断を再発見するはめになる」レベルの決定事項・罠のみ。

## ファイル構成

- `common.rs`: FE/REとFEIVが共有する部品。`PanelError`（共有エラー型）・`PanelDimension`・`EffectNames`・`PanelIndex`（個体・時点の索引と効果の列名）・`TimeKeys`・`quasi_demean_column`/`quasi_demean_two_way`・`WithinTransform`・`ensure_no_singleton_groups`・`ensure_no_zero_variance_columns`・`validate_balanced_panel`・`time_varying_regressor_indices`・cov_type別の共分散行列と推論の自由度を求める`panel_cov_params`（`PanelCovType`/`PanelEffects`。`FeCovType`/`ReCovType`/`FeEffects`/`ReEffects`はその型別名）。FE固有の補正（フルレバレッジ`leverage_full`・fixest流のK`fe_cluster_k_correction`・2グループ退化の検査`two_group_split_is_degenerate`）は`PanelStructure::FixedEffects`、REは`RandomEffects`で選ぶ。FEIVは`X̂`と構造残差を`PanelCovInput`に渡す想定。`FeInput`版の`within_transform_*`/`validate_no_*`はそのラッパー。推論表は`shared/inference.rs`の`inference_table`をFE・RE・2SLS・GMMが共有する。RE固有のハウスマン補助回帰（`re_hausman_test`）はK（`2k+1`）が違うため`panel_cov_params`を使わない。
- `fe.rs`は外から見える面（`FeEstimator`の構造体・getter・`fit`と`fixed_effects`の契約と1行委譲・`FeInput`等の再エクスポート）だけを持つファサード。ロジックは`fe/`の子モジュールに置く: `input.rs`（`FeInput`・`FeEffects`・`FeCovType`）・`within.rs`（within変換と事前検証）・`fit.rs`（`fit_fe`。`fit`のオーケストレーション）・`r_squared.rs`（between・overall R²）・`fixed_effects.rs`（`FixedEffects`と固定効果の復元）・`test_support.rs`（`#[cfg(test)]`の共有フィクスチャ）。テストは各ロジックと同じファイルの`mod tests`に置き、`fit`を通す統合的なテスト（fixest・linearmodelsとの照合、cov_type別、DK・クラスターの事前検証）と`mod proptests`は`fit.rs`にある。子は親のprivateフィールドに触れるため、構造体のフィールドはprivateのまま`fit.rs`が組み立てる。
- `re.rs`も同じ形のファサード（`ReEstimator`の構造体・getter・`fit`と`fit_with_variance_method`の契約と委譲・`ReInput`等の再エクスポート）。ロジックは`re/`の子モジュールに置く: `input.rs`（`ReInput`・`ReEffects`・`ReCovType`）・`variance.rs`（Swamy-Arora分散成分・内部FE・エンティティ平均・between回帰）・`variance_method.rs`（`VarianceMethod`・Wallace-Hussain・Amemiya・`variance_components`による3法の振り分け）・`transform.rs`（θ計算と準偏差変換）・`fit.rs`（`fit_re`）・`r_squared.rs`・`hausman.rs`・`test_support.rs`（`#[cfg(test)]`の共有フィクスチャ）。テストは各ロジックと同じファイルの`mod tests`に置き、`fit`を通す統合的なテスト（plm・linearmodelsとの照合、cov_type別、Mundlak・2-wayの検証）と`mod proptests`は`fit.rs`にある。
- `fe_iv.rs`: `FeIvInput`（入力型のみ。推定器は未実装）。`y`と役割別の列（`x_exog`・`x_endog`・`instruments`）を列スライスで持ち、定数項は持たない。役割ごとの列と名前は`RoleColumns { names, columns }`にまとめて渡す。個体・時点の索引は`PanelIndex`で、`PanelIndex::new`が観測数との整合を検証する（`validate_panel_input`と共有する`validate_panel_index`。検査の順序は列の長さ→entityの長さ→timeの長さ→entityのキー）。空の役割は入力型では受理し、`x_endog`・`instruments`が空であることの拒否は`engine_pybind`、操作変数の数の不足は推定器が担う（`IvInput`と同じ層分け）。`FeInput`/`ReInput`はまだ`PanelIndex`を使わず自前の`entity_codes`/`time`/`effect_names`を持つ。

## 全体に共通する決定

- **`fit()`の冒頭で`crate::shared::parallelism::ensure_serial()`を呼ぶ**（faerのグローバル並列度を`Par::Seq`に固定する。理由は`engine/src/linear/CLAUDE.md`「faerのグローバル並列度」）。回帰ガード（`fe_estimator_fit_pins_faer_global_parallelism_to_seq`等）を他系統に倣って入れる。
- **`engine`はpolars非依存**。グループ集約は、コード化済みの`entity`（`GroupCodes`、長さ`n`、行はパネル観測順）を受け取る（`from_group_codes`。ラベルの`String`列から作る`from_columns`は`#[cfg(test)]`の簡便版）。
- **整数コード（`GroupCodes`、`shared/group_codes.rs`。OLS・nonlinear・IVのクラスター集計とも共有）**: entity・timeは`engine_pybind`が行ごとの`String`を作らずに整数コード化して渡し、within変換・準偏差変換・エンティティ平均/R²・θ計算・singleton/件数チェック・cluster/DKの集計はコードで配列を直接引く。`String`キーの`HashMap`/`BTreeMap`で列ごと・統計量ごとに引き直すとn=1,000,000で1列約0.2秒かかり、FE/REの計算時間の大半になる（コード化後はRE約4秒→約0.9秒、FE約1.5秒→約0.25秒）。**コードはキーの辞書順に振る**（`BTreeMap`の反復順と同じ。グループ間加算の順（クラスターの`Σ_g S_g S_g'`）・between回帰の行順を固定するため。時点だけは`TimeKeys`が値の順序のコードを振る）。グループ内の行は観測順（`group_indices`は安定な計数ソート）。グループ間加算があるパネル系の実装は、このコード順で回すこと。
  - 入力の次元検証は`validate_panel_input`（x列→entity長→time長→entityのキー有無の順）を`FeInput`/`ReInput`が共有する。`FeEstimator::fit`は冒頭で`two_way_time(effects, &input)`を一度だけ解決し（2-wayで`time`が無ければ`TwoWayRequiresTime`）、以降の1-way/2-wayの分岐はその`Option<&GroupCodes>`で行う。
  - RE本体の内部FEは`FeInput::from_re_input`で`ReInput`のコードごと作り、作り直さない。
- **`quasi_demean_column`は列単位の関数**で、呼び出し側が`y`と`x`の各列に適用する。**FEはこの関数の`θ_i = 1.0`の特殊ケース**、REは`θ_i = 1 - sqrt(σ_ε² / (T_i·σ_u² + σ_ε²))`。θはエンティティコード順の`&[f64]`（長さ`n_groups`）で渡す。グループ平均は返さない（`fixed_effects()`は`fit()`が保持する変換前の入力と`params()`から再計算する）。契約違反（`entity`と列の長さ不一致・`theta`の長さがグループ数と不一致）は`assert!`/`expect`でpanicする（内部契約違反でありユーザー入力起因ではない）。
- **cov_typeの計算は`panel_cov_params`に集約し、数式をFE/REで複製しない**。`shared::covariance`の`classical_cov_params`/`hc_cov_params`/`cluster_cov_params`はそのまま使えない（HC1の補正は`n/df_resid`、HC2/HC3のレバレッジ、Clusterの`K`がFE固有）。蓄積`Σ_g S_g S_g'`は`cluster_meat`、補正式は`cluster_correction`を共有する。
- **`Dk`の`time`は必須の`TimeKeys`で、`FeInput.time_keys()`にはフォールバックしない**（どの列がDKの時点か呼び出し側が明示しない設計は、意図と違う列が選ばれても気づけないため）。`ReInput.time`は2-wayの時間次元専用。
- **`TimeKeys`の順序は呼び出し側が指定する**: 数値は数値順、日付・日時は時系列順、`Enum`は定義順。文字列の辞書順は`1, 10, 11, 2, ...`と時間順がずれて標準誤差が黙って変わるため使わない（`TimeKeys::lexicographic`・`FeInput::from_columns`はISO 8601日付やゼロ埋め年月向けの簡便版）。
- **DK/クラスターの事前検証**: クラスター数・時点数が検定する係数の数以下だと共分散部分行列が構造的に特異になる。入力から判定できる場合は共分散計算の前に`InsufficientClustersForInference`/`InsufficientDkPeriodsForInference`（`validate_dk_periods_cover_tested_coefficients`）で弾く。数値的な特異性判定に任せると、DK共分散のrankが`T-1`以下で理論上0の固有値に乗る丸め誤差が閾値をすり抜け、`1e13`級の無意味な統計量を黙って返す（`T=6`・`k=6`で20シード中13回）。
- **2グループ退化（`DegenerateDkTwoPeriods`/`DegenerateClusterTwoGroups`）**: FEのDKで`t_periods=2`、またはClusterで`G=2`のとき、全エンティティが2グループに1観測ずつだとwithin変換で観測が符号反転しグループスコアが恒等的にゼロになる。`t > q`/`G > q`は`k=1`で通ってしまい、`1×1`行列は`ensure_well_conditioned_symmetric_matrix`の相対閾値でも検出できないため、SE≈1e-16・F≈1e30を黙って返す。`two_group_split_is_degenerate`で`k >= 1`のときだけ事前に弾く。**2-wayではtime方向も同じ構造**（エンティティ2つのパネルをentityでクラスタリングすると全時点が2クラスターに1観測ずつになる）なので、entity方向だけ見る判定では取りこぼす。REは残差がwithin変換されないため対象外。`Dk.time`の上書き列は`FeInput`の検証を通らないため、DKアームの先頭で長さを検証する。

## FE

- **`FeEstimator`は`OlsEstimator`を経由せず`shared::least_squares::least_squares`を直接呼ぶ**（FEが使うのは係数・残差・`(X̃'X̃)⁻¹`・適合度だけで、標準誤差・F検定は`cov_type`ごとにFE自身が計算し直すため）。`x=[]`（k=0）は`least_squares`が受理するので、engine層は固定効果のみのモデルを受け付ける（`engine_pybind`層が拒否する）。完全適合・極端なスケール差の入力で返るエラーは`WithinRegressionFailed`ではなく`FTestFailed`（付く`stage`が違うだけで、Pythonでは`MATRIX_NEAR_SINGULAR`の`ComputationError`）。極端なスケール差のテストは、残差が総平方和の`k·ε`倍を超える大きさのノイズで作ること。
- **2-wayは「entityでquasi-demean → timeでquasi-demean」の2段階**（バランスパネルで閉形式と一致する。導出は`fe-spec.md`3.1節）。`validate_balanced_panel`は件数の一致`n_obs == n_entities * n_periods`だけでは「あるペアの重複と別ペアの欠落が相殺する入力」を見逃すため、`(entity, time)`ペアの重複も検証する。
- **singletonはwithin変換の前に生のentity/timeから数える**（下流の特異行列エラーとして偶発的に検出される形にしない）。`validate_no_singleton_groups_two_way`は`time`の存在確認を最初に行い（`within_transform_two_way`と同じ順序）、その後entity→timeの順で検出する。
- **分散ゼロの検出の閾値は相対値**: `column_is_zero_variance`（`shared/validation.rs`）が、within変換後の列の標準偏差を「変換前の元の列の最大絶対値」×`n`×`f64::EPSILON`と比較する。変換後の値自身をスケール基準にすると自己参照になり閾値が機能しない。
- **自由度**: `df_model = k + neffects`（2-wayの`neffects`は`n_entities + n_periods - 1`）。AIC/BICはペナルティ項の乗数だけ`k`から`df_model`に差し替える。t値・p値・信頼区間・F検定の自由度は`cov_type=Cluster`で`G-1`、`Dk`で`t_periods-1`。
- **F統計量の検証**: `linearmodels`（`cov_type="unadjusted"`）の`f_statistic`と直接比較し、`fixest::wald()`と全`cov_type`×1-way/2-wayで機械精度で一致する（`tests/panel/test_fe_crosscheck.py`）。**`wald()`は分母自由度を`max(df2, df1+1)`に切り上げるため、`G-1<=q`・`df_resid<=q`の境界ではp値が`summary`のt検定と食い違う。参照値のp値は統計量と`degrees_freedom(model,"t",vcov)`から`pf()`で計算し直している。** `k=1`のケースは「1自由度のF検定は両側t検定と等価」（`f_statistic = test_stat²`）で全`cov_type`を検証する（`cov_type`別の`cov_params`・`df_resid`が正しく`wald_f_test`に渡っているかの回帰ガード）。
- **`linearmodels.PanelOLS`は`aic`・`bic`を提供しない**ため、この2つは`fixest`との比較のみ（2系統検証の例外）。2-wayのwithin R²も`linearmodels`はentityのみのdemeanで固定のため`fixest`の`fitstat(model, "wr2")`と比較する。
- **`r_squared_between`に`T_i`ベースの重み付けをしてはいけない**: `linearmodels`の`_prepare_between`は不均衡パネル用の重み`w_i=T_i/mean(T)`を計算するが、サンプルウェイト未指定なら`_rsquared`が`1.0`に上書きする。FEは`weights`を持たないので常に無効。バランスパネルのテストでは`w_i=1`に退化して気づけず、不均衡パネルで初めて`linearmodels`との不一致が出る（`fe_estimator_fit_one_way_r_squared_between_matches_linearmodels_on_unbalanced_panel`で固定）。ループ本体や分岐が一部の入力でしか通らないコードは、通らない入力でも検証すること。
- **`fixed_effects()`の2-way正規化**: 基準時点を`time`の時間順で最初の値`t_ref`に固定する（観測順に依存しない決定的な選び方）。`fixest::fixef()`の基準時点は観測順で最初に現れた値に見え、数値が一致するのは基準時点が一致する入力に限る。
- **Dkの`bandwidth == t_periods - 1`ではfixestと一致しない（fixest側のバグ、本実装は標準カーネルを維持）**: fixestのC++実装`cpp_driscoll_kraay`が、ラグの個数`L=bandwidth+1`に`L > T-1`の上限を課すoff-by-oneで、この境界でだけ最終ラグ項を落とす。fixestとの比較は`bandwidth <= T-2`で行い、境界は`plm::vcovSCC(maxlag=T-1)`・`panel_driscoll_kraay_cov_params`の定義式との単体テストで検証する（`fe-spec.md`3.3節）。`bandwidth=Some(0)`（ラグ項なし）は`FeCovType::Cluster { groups: Some(time) }`と数式的に同一になるため、2つの独立実装の一致をテストしている。
- **HC0は提供しない**（仕様判断。fixest 0.14.2は`vcov = "HC0"`を受け付けないが、plm 2.6.7は提供するので、他パッケージの有無は理由にしない）。

## RE

- **REの内部FE（σ_ε²用）は`FeInput`と同じsingleton検証を継承する**ため、`T_i=1`のエンティティがあるデータは`PanelError::SingletonGroup`で失敗する。`linearmodels.RandomEffects`はsingletonを処理できるので、本実装は`linearmodels`より厳格にsingletonを拒否する。ベンチマークデータは全エンティティ`T_i>=2`にすること。
- **時間不変の説明変数を許容する**（`re-spec.md`5章）。`swamy_arora_variance_components`が`time_varying_regressor_indices`で時間変化のある列だけを内部FEに渡し、`VarianceComponents.time_varying`で元の列に対応づける。**この対応を使うのは`re_r_squared_within`（`fe.within_input().x()`のm列目の係数は`params[time_varying[m] + 1]`）と`re_hausman_test`の2か所**。`fe.within_input().x()`の列数は`input.x()`ではなく`k_tv`なので、`debug_assert_within_reuse_contract`も`k_tv`と照合する。定数列や定数でない時間不変列同士の共線は、between回帰では別名として落ち、最終回帰の特異性（`QuasiDemeanedRegressionFailed`）で検出される。**`plm::phtest(method = "aux")`は時間不変の列があると検定する係数を位置で選び間違えるため参照にできない**（`benchmark/panel/run_plm_hausman_tilde_benchmark.R`が名前で選ぶ）。不均衡パネルでは`plm`とσ_u²の定義が違い、時間不変変数の係数に大きく（`T_i`が2〜10に偏ると13%）出るため、`plm`と直接は比較せず、仕様どおりの手計算（`tests/panel/test_re_time_invariant.py`）と比較する。
- **between回帰は平均が単位間で一定の列を落とし、`K_b`にも数えない**（`between_ssr_and_df`。`plm`と同じ。落とさないと切片と共線で特異になる）。1-way・2-wayとも同じ関数で、`OlsEstimator`は経由しない。さらに別名の列（相関ランダム効果＝Mundlak型）は`independent_columns_in_order`（Rの`lm`と同じ、列順で後ろを落とす）でランクで落とす。許容誤差`1e-7`は非中心化ノルムに対する相対値なので、平均に対して変動が`1e-7`倍以下の列は定数に近い列として落ちる。between回帰は切片+傾き`k`個の`k+1`パラメータのため`n_entities > k+1`が必要（`linearmodels`も`n_entities=k+1`で`ZeroDivisionError`になる）。
- **ハウスマン検定は`X̃`の識別できない列を検定対象から外す**: `x*_j - x̃_j`が全観測で一定になる列は未変換の定数項と共線になる（`hausman_within_column_is_aliased`）。`None`になるのは検定できる傾き係数が無い場合のみで、補助回帰のランク落ち・クラスター数不足・共分散部分行列のほぼ特異性は`PanelError::HausmanTestFailed`で`fit()`全体を失敗させる。**定数項は準偏差変換しない**（`plm::phtest(method = "aux")`に合わせる）。バランスパネルでは`plm`と1e-9で一致し、不均衡パネルはσ_u²推定式の差でクロスチェック水準になる。
- **F統計量はWald二次形式**（`linearmodels`の`f_statistic`はSST/SSR方式で、極端な不均衡パネルで負値になる）。`linearmodels`との比較は`f_statistic_robust`（`cov_type`連動のWald二次形式）を使う。`plm`のp値は使わない（`pwaldtest`の分母自由度は`vcov`の種類で決まり本実装の規約と一致する保証がない）。不均衡パネルの`plm`との差（Swamy-Arora分散成分の推定差）は`cov_type`別にhc2 8.7e-4・hc3 8.5e-4・cluster 1.3e-3・dk 6.7e-3まで出る。そのため標準誤差・F統計量は、`linearmodels`の分散成分を与えて準偏差変換したデータへの`plm`の`vcov`系と機械精度で比べる（`run_plm_re_given_variance_benchmark.R`）。
- **HC2/HC3の参照実装が`linearmodels`に無い**（`RandomEffects`・`PanelOLS`とも単一の"heteroskedastic"＝HC1相当しか持たない）。`plm::vcovHC(fit, method="white1", type="HC2"/"HC3")`をクロスチェックに使う。Cluster/HACの小標本補正はStata・R型（`G/(G-1)·(n-1)/(n-K)`、HACは`G`の代わりに時点数、t分布の自由度は`G-1`/`T-1`）で`linearmodels`とは一致しないため、`plm::vcovHC(method="arellano", type="sss")`・`vcovSCC(type="sss")`を参照値にする。
- **`ReEstimator`は常に自前のフィールド（`std_errors`/`test_stats`/`p_values`/`conf_lower`/`conf_upper`/`cov_type`）を保持する**（`estimator()`委譲に頼らない。一部のcov_typeだけ委譲する非対称なAPIを避けるため）。REは`cov_type`によらず`extra_df=0`（設計行列に省略された固定効果ダミーが無い）。HC2/HC3のレバレッジも素の`h_ii`。`estimator().f_statistic()`/`r_squared()`は`include_intercept=false`委譲の都合で誤る（`k_constant`が0扱い）ので使わない。
- **σ_ε²=0の2つの下位ケースを区別する**: (1) σ_ε²=0かつσ_u²=0の同時ゼロは`θ_i`が`0.0/0.0`でNaNになり、全観測にNaNが伝播する（実務ではほぼ起きないので未対応。問題になった時点で`ReEstimator::fit`で弾くか検討する）。(2) σ_ε²=0単独は`θ_i=1`に収束し切片復元用の定数列が全ゼロになるが、内部FEが完全適合を先に`WithinRegressionFailed{PerfectFit}`（`stage=VARIANCE_COMPONENT_WITHIN_REGRESSION`）で止めるため最終回帰には到達しない。
- **`quasi_demean_two_way`は2段階の`quasi_demean_column`では代替できない**: `θ₃ = θ₁ + θ₂ - 1 + σ_ε/σ₄ ≠ θ₁θ₂`。`σ_u² = 0`または`σ_λ² = 0`なら`θ₃`は定義式から厳密に0（丸め誤差を残さないよう明示している）。between回帰は2-wayで個体平均・時点平均に独立に当てはめる。
- **`variance_method`**: バランスは`plm`の`dfcor = 1`の閉形式、不均衡の1-wayは`dfcor = 3`のトレース項の式で、**両者はバランスパネルでも値が異なる**（1行落とすと`wallace_hussain`・`amemiya`の値は連続でない）。1-wayは観測数で判定し、観測数が等しく時点がずれたパネルは`plm`（`is.pbalanced`は同じ時点集合も要求）と値が合わない。`amemiya`はwithin変動の無い列を`AmemiyaRequiresWithinVariation`で拒否する。σ_ε²が0以下は`NonPositiveIdiosyncraticVariance`（`plm`は0に切り上げてθがNaN）。**proptestの不変性（スケール・シフト・並べ替え）は式が一貫して誤っていても通る**ため、トレース項の式は観測ごとの行列に展開した参照実装との一致（`trace_forms_match_the_observation_level_reference`、バグ注入で確認）で守る。
- **RE（1-way・2-way）のテスト基盤**: 2-wayの`plm`参照値は`tests/fixtures/benchmarks/re_two_way.json`（`generate_re_two_way_fixtures.py`）、時間不変・時点間のみ変わる列は`re_time_invariant.json`、`variance_method`は`re_variance_method.json`。仕様どおりの独立な手計算は`tests/support/_re_oracle.py`で、`plm`が`empty model`で失敗する入力の唯一の参照になる。許容誤差は`tests/support/_tolerances_panel.py`。`engine/src/panel/re/`の単体テストの小パネル（6×4）の`plm`値は`re_two_way.json`の`small_hand_*`と同じ値（engineがJSONに依存しないため埋め込んでいる）。

## 完全適合・定数の被説明変数

- `FeEstimator::fit`は、説明変数の分散ゼロ検出の直後に、被説明変数のwithin変換後の分散を同じ相対閾値で調べ、残らなければ`PanelError::OutcomeConstantWithinEntity`（`ValidationError`）にする。2-wayの個体効果+時点効果だけで説明される`y`もこの相対判定で拾う（厳密な等値だと、`0.1`を3回足して3で割った平均が`0.1`と一致しないために見逃す）。
- `least_squares`の直後、共分散より前に`is_perfect_fit(ssr, Σỹ², k)`を調べ、完全フィットなら`WithinRegressionFailed { source: PerfectFit }`（`stage=WITHIN_REGRESSION`）にする。
- REは内部FE（分散成分の推定）がこの2つを担い、RE自身は被説明変数を調べない。`WithinRegressionFailed`は`within_for_variance_component`が`VARIANCE_COMPONENT_WITHIN_REGRESSION`を付けて包み、`OutcomeConstantWithinEntity`は`stage_allowed=false`なので包まれず素のまま返る。REの最終回帰とハウスマン補助回帰は`OlsEstimator::fit_auxiliary`（完全フィット・定数の判定なし。被説明変数が準偏差変換後の値で、判定の基準が当てはまらない）。

## 踏んだ罠: エンティティ平均が全て一致する退化データ

- 全エンティティの`ȳ_i.`が完全に一致するデータは、REのbetween R²のTSSが0になる条件であり、between回帰が「切片=共通の平均値・傾き=0」の完全な当てはめ（`SSR_between=0`）になる条件でもある。between回帰（`between_ssr_and_df`）は残差平方和と自由度しか使わず推論統計量を計算しないので、平均が全て0でも`σ_u² = max(0, 0 - σ_ε²/t_bar) = 0`で成功する（`swamy_arora_variance_components_does_not_panic_when_entity_means_are_all_zero`）。`OlsEstimator`の推論表（`compute_inference_stat`）は`0/0=NaN`のt統計量を`p_value=NaN`として返し、panicしない（`shared/inference.rs`のテストで固定）。係数の標準誤差が0になる退化データを`OlsEstimator`に渡すテストを書くときは、この挙動に注意すること。

## PanelError

- FE/REで共有（`FeError`/`ReError`は作らない）。`CommonError`を`#[error(transparent)] Common(#[from] CommonError)`で包む。
- `impl ErrorInfo for PanelError`の`report()`が全バリアントを`_`なしで列挙し、カタログの`code`・`params`に写す（`ValidationError`/`ComputationError`の別は`code`のカタログのクラスで決まる）。`code`の表は`docs/spec/fe-spec.md`3.6節。新しいバリアントを足したら`report()`に`code`を足す（足し忘れは`engine`のコンパイルエラー）。`engine_pybind`の`panel_error_to_pyerr`は`to_pyerr(&err)`を呼ぶだけで更新は要らない。到達不能な状態（`IdentifierDimensionMismatch`・`TwoWayRequiresTime`）は`INTERNAL_ERROR`に写す。
- 回帰の失敗を包むバリアント（`WithinRegressionFailed`・`FTestFailed`・`BetweenRegressionFailed { means }`・`PooledRegressionFailed`・`QuasiDemeanedRegressionFailed`・`HausmanTestFailed`。いずれも`#[source] source: LeastSquaresError`）は`#[from]`を使わず明示的に`.map_err`で包む（`CommonError`が2経路で`PanelError`になる曖昧さを避けるため。`IvError::FirstStageFailed`と同じ判断）。包みは文面を持たず、`report()`が原因の`code`に`Stage`を付ける（`staged_report`。`stage`を付けられない`code`、例えば`confidence_level`の範囲違反は包まずそのまま返す）。対象が異なる回帰は別バリアントにする（FEのwithin回帰・REのbetween回帰・REの最終回帰・F検定）。
- `InStage { stage, source: Box<PanelError> }`（`PanelError::in_stage`）は、別の`PanelError`を起きた計算の文脈つきで包む（REの分散成分推定に使う内部FEの自由度不足など）。`stage_allowed`な`code`にだけ使える。
- **`SingletonGroup`は列名`column`を持つ**: `report()`は`argument`を`"effects"`に固定し、`column`と`group`を`params`に載せる。列名は`EffectNames`（`entity`・`time`の2つの`String`。`FeInput`/`ReInput`が保持）で運び、`with_effect_names`で設定する。**エラーの`column`に載せるためだけの値で、計算には使わない**。既定は`"entity"`・`"time"`。
- `confidence_level`が不正な場合、REでは`QuasiDemeanedRegressionFailed`ではなく`WithinRegressionFailed`として伝播する（分散成分推定の最初の委譲が真っ先に検証するため）。

## property-basedテスト（`mod proptests`）

- FE（`fe/fit.rs`）は`fit`レベルで「yへのentity/time定数加算」「行並べ替え＋entityラベル付け替え」「yスケール線形性」「LSDVオラクル（傾き・Classical SE）」を検証する。REは「θの値域`[0,1)`」「`σ_u²=0`でpooled OLSと一致」「行並べ替え＋ラベル付け替え」（ハウスマン統計量も含む）。ケース生成器はFE/REで別定義（FEは2-wayのためバランスパネル、REは不均衡パネル固定）。
- **`quasi_demean_column`はFE・REの両方の土台**なので、バグ注入は`common.rs`側で行うと両方のプロパティを検証できる。ただし`y=Σx+ノイズ`のDGPでは「グループ平均を定数倍ずらす」ような注入は`y`と`x`で相殺して二次効果に埋もれ、LSDV/行順序系プロパティでは検出できない。注入は「観測単位で値を汚す」（`n>20`かつ値>5のときだけ+1e-3等）か「行順序依存にする」（グループのk番目の観測を和から除く）形にする。
- `σ_u²=0`でのpooled OLS一致は、entity効果なしのDGPだとSwamy-Arora推定量の`max(0)`により約半数のケースで自然に成立するため、`prop_assume!(sigma2_u == 0.0)`で棄却しても`too many rejects`にならない。
