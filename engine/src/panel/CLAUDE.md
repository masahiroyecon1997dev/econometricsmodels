## 実装済み（現状）

- `common.rs`: `PanelError`（FE/RE共有エラー型、Issue #172。`entity`/`time`の長さ不一致用`IdentifierDimensionMismatch`をIssue #175で追加）＋ `PanelDimension` enum ＋ `quasi_demean_column`（θパラメータ化した準偏差変換、Issue #173）＋ `hausman_statistic`（古典的ハウスマン検定の統計量、Issue #174）。
- `fe.rs`: `FeInput`（入力データ型、Issue #175）。`y: Vec<f64>` / `x: Vec<Vec<f64>>` / `entity: Vec<String>` / `time: Option<Vec<String>>`等を保持する薄い入れ物で、`OlsInput`/`IvInput`と異なり`faer::Mat`は組み立てない（`quasi_demean_column`が列単位・`&[f64]`で動く設計のため、`fit()`実装（Issue #178）が生の列をそのまま渡せる。詳細は`fe.rs`モジュールdoc）。`from_columns`は次元検証（`y`↔各`x`列・`y`↔`entity`・`y`↔`time`）のみ行う。
  - `within_transform_one_way`/`within_transform_two_way`（within変換、Issue #176）も実装済み。**2-wayは閉形式の二重デミーニング`ỹ_it = y_it - ȳ_i. - ȳ_.t + ȳ..`を直接計算せず、「entityでquasi-demean（θ=1）→ その結果をtimeでquasi-demean（θ=1）」という2段階の`quasi_demean_column`呼び出しで実装している**（バランスパネルでは数学的に閉形式と厳密に一致することを導出済み・rust-reviewerが独立検算のproptestで検証済み。導出は`fe.rs`モジュールdoc参照）。バランスパネル検証（6.4節）は`validate_balanced_panel`（`fe.rs`内private）が担う: 単純な`n_obs == n_entities * n_periods`のカウント一致だけでは「あるペアの重複と別ペアの欠落が相殺する入力」を見逃すため、`(entity, time)`のユニークペア数が`n_obs`と一致すること（重複なし）も併せて検証する。`time`が未指定なら`PanelError::TwoWayRequiresTime`。
  - `validate_no_zero_variance_regressors`（分散ゼロ説明変数の検出、Issue #177、6.7節）も実装済み。`within_transform_one_way`/`within_transform_two_way`どちらの出力にも使える1-way/2-way共通ロジックで、時間不変変数（1-way）・2-wayでtime FEと完全共線な「エンティティ間で変動しない列」を同じチェックで検出する。**閾値は絶対値ではなく相対値**（`.claude/rules/rust-style.md`「線形代数」の特異性判定の方針と同じ）: `column_is_zero_variance`（`fe.rs`内private）が、within変換後の列の標準偏差を「変換前の元の列の最大絶対値」×「観測数`n`」×`f64::EPSILON`と比較する。変換後の値自身をスケール基準にすると自己参照になり閾値が機能しなくなるため、変換前の値を基準にする（詳細な導出は`column_is_zero_variance`関数docコメント参照）。rust-reviewerレビュー済み（`assert_eq!`での列数・列長の内部契約チェック、n=0境界テストの追加を反映）。
  - `validate_no_singleton_groups_one_way`/`validate_no_singleton_groups_two_way`（singleton検出、Issue #179、6.5節）も実装済み。**within変換の前に生の`entity`/`time`列を直接見る設計**（`within_transform_*`を呼ばない）——6.5節が要求する「下流の特異行列エラーとして偶発的に検出される形にはしない」を満たすため。1-wayはentityのみ、2-wayはentity・time双方を対称に検出する。内部の`reject_singleton_group`（`fe.rs`内private）は`HashMap`でカウント→観測順に再走査して最初のsingletonを報告する2パス方式（グループ間の浮動小数点加算順序に依存しないカーディナリティ集計のみのため`HashMap`でよい、`quasi_demean_column`と同じ理由）。`validate_no_singleton_groups_two_way`は**`time`の存在チェックを最初に行う**（`within_transform_two_way`と同じ順序に揃える設計判断、rust-reviewer指摘を反映）——その後entity→timeの順でsingletonを検出する（両方該当時はentity側を報告、`FeInput`のフィールド順に合わせた恣意的な優先順位）。
  - `FeEffects`（`OneWay`/`TwoWay`）・`FeEstimator`（`OlsEstimator`への委譲、Issue #178、4.3節）も実装済み。`FeEstimator::fit`は`OlsInput::from_columns`を`include_intercept=false`固定で呼ぶ（Frisch-Waugh-Lovell定理によりwithin変換後のOLS点推定はFE推定量`β̂`と数学的に一致する）。`OlsEstimator::fit`自体は常に`cov_type=CovType::Classical`固定で呼ぶ（`β̂`・残差の取得のみが目的で、`cov_type`ごとの標準誤差はFE自身が独立に計算し直すため、委譲先のcov_type選択は結果に影響しない、#181で確定）。パイプラインは「singleton検出（#179）→within変換（#176、2-wayはバランスパネル検証を内包）→自由度検証（#180）→分散ゼロ検出（#177）→`OlsEstimator::fit`への委譲→`cov_type`別の共分散行列計算（#181）→自由度調整後の統計量再計算（#180）」の順（`FeEstimator::fit`のdocコメント参照）。`OlsInput::from_columns`/`OlsEstimator::fit`が返す`LeastSquaresError`は`PanelError::WithinRegressionFailed { source }`に`.map_err`で明示的に包む（`common.rs`の方針、`#[from]`は使わない）。1-way/2-wayの切り替えは`FeEffects` enum（`bool`ではなく、`CovType`と同じ「小さな固定選択肢の公開enum」パターン、ユーザーとの相談で決定）を使う。将来`FeOptions`（Issue #186）が導入されたら、その一部として統合される想定の暫定パラメータ。
  - **自由度調整（Issue #180、6.3節）も実装済み**: `df_model = k + neffects`（1-wayは`neffects=n_entities`、2-wayは`neffects=n_entities+n_periods-1`。entity/timeダミー間の定数項ぶんの重複を`+1`補正）、`df_resid = n - df_model`。`n <= df_model`なら`PanelError::InsufficientDegreesOfFreedom`（この検証は`OlsEstimator::fit`自身の`n<=k`チェックより常に厳格——`neffects>=1`のため`df_model>k`が恒常的に成り立つ——なので、`FeEstimator::fit`経由でOLS側の`InsufficientObservations`が発生することは構造的にない）。t値・p値・信頼区間の自由度は`cov_type`によらず常に`df_resid`（3.3節、#181実装時にlinearmodelsで確認）で、`crate::inference`の共有ヘルパー（OLS自身と同じロジック）から計算する。AIC/BICは`log_likelihood`自体は`SSR/n`のみに依存しdf非依存の式のため`OlsEstimator::log_likelihood()`をそのまま再利用し、ペナルティ項の乗数だけ`k`から`df_model`に差し替える。**F統計量はこの時点では未対応**（issue本文が「検定統計量（t検定）」と明示的に限定しているため、`estimator().f_statistic()`/`f_p_value()`は`df_resid_ols`・`CovType::Classical`ベースのまま）。
  - **検証の例外（Issue #180）**: Python主リファレンスの`linearmodels`（`PanelOLS`）は`aic`・`bic`を一切提供しない（ソースコード確認済み。`rsquared_within`/`between`/`overall`/`inclusive`・`loglik`のみ）ため、この2つの検証はRクロスチェック（`fixest`）のみで行う（通常の「Python主リファレンス+Rクロスチェック」の2系統検証の例外、ハウスマン検定（5.3節）と同型）。上記の式は`fixest::feols`の`AIC()`/`BIC()`と数値的に一致することを実地検証済み（`fe_estimator_fit_one_way_matches_fixest_reference`/`_two_way_matches_fixest_reference`で固定）。
  - **パネル固有R²（Issue #183、2.3節）も実装済み**: `r_squared_within`/`r_squared_between`/`r_squared_overall`の3フィールド（`bareのr_squared_adj`は廃止、2.3節が明示的に要求）。素朴に「実際に使ったFE構造でdemeanしたR²」を3種とも定義すると考えがちだが、`linearmodels==7.0`のソース確認・実地数値検証で以下が判明している（ユーザーとの相談で決定、2026-09-12。詳細な式・導出は`fe.rs`モジュールdoc「パネル固有R²」）:
    1. **`r_squared_within`は「実際に使ったFE構造でdemeanした残差」を採用**（1-wayはentityのみ、2-wayはentity+time）——`estimator().r_squared()`をそのまま使う。**`linearmodels`自身の`rsquared_within`は常にentityのみのdemeanで固定**（2-wayモデルでも時間効果を含めない）という別定義のため、2-wayでは意図的に数値が食い違う。2-wayの検証はユーザー指示により`linearmodels`ではなく`fixest`の`fitstat(model, "wr2")`（"Within R2"）を使う（実地検証で1-way・2-way双方の数値一致を確認済み。AIC/BICと同型のRクロスチェック例外）。
    2. **`r_squared_between`/`r_squared_overall`は`linearmodels`の`_rsquared`と完全一致**させる。FEのxには定数列を含められない（含めれば`validate_no_zero_variance_regressors`が弾く）ため`has_constant=False`分岐（非中心化TSS）が常に適用される。`r_squared_overall`は固定効果の切片項を一切含めない元の`y`・`x`に`β̂`だけを当てはめた残差ベース（`estimator().residuals()`＝FWL定理による固定効果込みの残差とは別物）。`r_squared_between`はエンティティ平均`ȳ_i.`・`x̄_i.`に`β̂`を当てはめた残差ベース。
    3. **`r_squared_between`にエンティティ観測数`T_i`による重み付けをしてはいけない罠**: `linearmodels`の`_prepare_between`自体は不均衡パネル用の重み`w_i=T_i/mean(T)`を計算するが、`_rsquared`側でサンプルウェイト（`weights`引数）が全て`1.0`（未指定）なら`w`を無条件に`1.0`へ上書きする。**FEは`weights`引数をサポートしない**（CLAUDE.md 1.3節）ためこの重み付けは常に無効。一度`T_i`ベースの重み付き版を実装し、バランスパネルのテストでは`w_i=1`に退化するため気づかず、不均衡パネルで初めて`linearmodels`との数値不一致（0.9448 vs 0.9438）が発覚して修正した（`fe_estimator_fit_one_way_r_squared_between_matches_linearmodels_on_unbalanced_panel`で固定。バランスパネルのみのテストだと重み付けロジックの分岐が一度も実質的に検証されない典型例、Issue #182のDKバンド幅ループと同じ教訓）。
    - 新規ヘルパー（`fe.rs`内private）: `fe_r_squared_between`・`fe_r_squared_overall`（`group_indices_by_key`をentity集計に再利用）。
  - **`cov_type`対応（Issue #181、3.1節・3.2節）も実装済み**: `FeCovType` enum（`Classical`/`Hc1`/`Hc2`/`Hc3`/`Cluster{groups}`/`Hac{bandwidth}`）を`OlsEstimator`の`CovType`とは別に新設（HC0を含まない、無効な組み合わせを型で表現不可能にする設計）。**`OlsEstimator`の既存cov_type計算式（`classical_cov_params`/`hc_cov_params`/`cluster_cov_params`）はそのまま流用できない**——linearmodels/fixestのソース確認・実地数値検証で判明した3点の相違（詳細は`fe.rs`モジュールdoc「`cov_type`対応」）:
    1. HC0はスコープ外（linearmodels・fixestともにパネル/FE向けのHC0オプションが存在しない）。
    2. HC1〜HC3は独自計算: HC1は小標本補正係数が`n/(n-k)`ではなく`n/df_resid`。HC2/HC3のレバレッジは、within変換後の設計行列ではなくLSDV相当のフルレバレッジ`h_ii_full = 1/T_entity(i) + h_ii_within`（1-wayは分割回帰＝Frisch-Waugh-Lovellのレバレッジ分解則、2-wayはさらに`+ 1/N_time(i) - 1/n`）でなければならない（fixestと数値一致確認済み）。
    3. Clusterも独自計算: OLSは`(G/(G-1))×((n-1)/(n-k))`というStata流の小標本補正を常に適用するが、linearmodels（FEの主リファレンス）はこの補正を使わず`n/(n-extra_df-k)`のみを使う。**`extra_df`はcluster変数とFEの関係で決まる**（linearmodelsの`_determine_df_adjustment`と数値一致確認済み）: 1-way FEで「クラスター変数がentityと同じか、entityを包含するより粗い分割（各entityが単一のクラスターに属する、`entity_nested_within_cluster`で判定）」なら`extra_df=0`（`cluster_col`省略時のデフォルト——entity自体——は常にこの条件を満たす）、それ以外（1-way FEでentityと無関係なクラスター変数、または2-way FE）は`extra_df=neffects`。
    - 新規ヘルパー（`fe.rs`内private）: `design_matrix_from_columns`（列→`faer::Mat`組み立て）・`xtx_inverse`（`(X̃'X̃)⁻¹`、`OlsEstimator`のprivateな`cov_params`を再利用できないため独立に計算し直す）・`leverage_within`/`leverage_full`・`fe_classical_cov_params`/`fe_hc_cov_params`/`fe_cluster_cov_params`・`entity_nested_within_cluster`・`group_sizes`。
    - `cov_type`のデフォルト（`"cluster"`、entity単位、3.2節）・`cluster_col`文字列パースは`engine_pybind`層（`FeOptions`、Issue #186以降）の責務。`FeEstimator::fit`自体はデフォルトを持たない。
  - **Driscoll-Kraay型パネルHAC対応（Issue #182、3.1節）も実装済み**: `FeCovType::Hac { bandwidth: Option<i64> }`。着手時に`linearmodels.panel.covariance.DriscollKraay`のソースを実地確認し、以下をユーザー承認済み（2026-09-12、詳細な式・導出は`fe.rs`モジュールdoc「Driscoll-Kraay型パネルHAC対応」）:
    1. **カーネルはv1でBartlett限定**（OLSの`CovType::Hac`と平仄を合わせる）。Parzen/QSへの拡張はIssue #313（未着手）。
    2. **バンド幅**は`linearmodels`のデフォルトルール`floor(4*(t/100)^(2/9))`（`t`=ユニークな時点数、OLSの`hac_lags`が観測数`n`ベースなのと違う点に注意）を`resolve_dk_bandwidth`で踏襲。明示指定は`[0, t)`範囲検証（`PanelError::InvalidHacBandwidth`）。
    3. **時系列順序は`time: Vec<String>`の辞書順とみなす**（`entity`と同じく同一性のみが意味を持つ列で順序情報を持たないため。ISO 8601日付・ゼロ埋め年度等、辞書順=時系列順になる形式で渡すことが呼び出し側の契約——`engine`側にこの契約のバリデーションは無い）。`fe_driscoll_kraay_cov_params`は`BTreeMap<&str, Vec<usize>>`で`time`をキーに集計し、辞書順＝時系列順を一致させている。
    4. **1-way/2-way両対応**。2-way FEは`time`が既に必須だが、1-way FEで`FeCovType::Hac`を指定したのに`time`が`None`なら`PanelError::HacRequiresTime`。
    5. スケールは`(n/df_resid) × (X̃'X̃)⁻¹ Ŝ (X̃'X̃)⁻¹`。linearmodelsは`cov_type="kernel"`で常に`extra_df=neffects`（`Cluster`と異なり`entity_nested_within_cluster`のような条件分岐が無い）かつデフォルト`debiased=True`のため、素直に本モジュールの`df_resid`と一致する。
    - **回帰テストとしての交差検証**: `bandwidth=Some(0)`（ラグ項なし）は`FeCovType::Cluster { groups: Some(time) }`（entityと無関係なクラスター変数、`extra_df=neffects`）と数式的に同一になるため、2つの独立実装（`fe_cluster_cov_params`/`fe_driscoll_kraay_cov_params`）の一致を確認するテストを追加している（OLSの`fit_hac_with_zero_lags_matches_hc0`と同型の手法）。
  - **固定効果自体（α_i）の復元（Issue #184、6.6節）も実装済み**: `FeEstimator::fixed_effects()`（`fit()`の戻り値本体には含めない別メソッド、IVの`first_stage()`と同じ方針）。1-wayは`FixedEffects::OneWay(BTreeMap<String, f64>)`、2-wayは`FixedEffects::TwoWay { entity, time }`。**1-wayは一意**（`α_i = ȳ_i. - x̄_i.'β̂`、切片が全てentityに吸収される設計のため正規化の任意性が無い）だが、**2-wayには正規化の任意性がある**（着手時に発見、ユーザー承認済み、2026-09-12）: `α_i`に定数`c`を足し`γ_t`から`c`を引いても同じ予測値になるため一意に決まらず、6.6節の式をそのままentity/timeに当てはめると大域平均が二重計上されるバグになる。**採用した規約: `time`の辞書順で最初の値`t_ref`を基準に`γ_{t_ref}=0`とし、`α_i`に大域的な水準を吸収させる**（DKの時系列順序規約と同じ、観測順に依存しない決定的な選び方）。**`fixest::fixef()`との数値一致は`t_ref`の選び方が一致する入力に限られる**——実地検証で`fixest`自身の基準時点選択は`time`列の辞書順ではなく観測順で最初に現れた値に見えることが判明（同じ`{entity,time}`ペア集合でも行の並び順を変えると`fixef()`の基準時点が変わる）。2-wayの正規化はどの`t_ref`を選んでも数学的に等価なため、`fixest`の観測順依存の挙動は再現せず辞書順の規約を優先する（ユーザーとの相談で決定。詳細な導出は`fe.rs`モジュールdoc「固定効果自体（α_i）の復元」参照）。新規ヘルパー（`fe.rs`内private）: `slope_only_residual`（`fe_r_squared_overall`と共有）・`group_residual_means`・`overall_residual_mean`。

## faerのグローバル並列度（Issue #283）

- FE/RE の `fit()` エントリを実装するときは、**冒頭で `crate::parallelism::ensure_serial()` を呼ぶこと**（faer のグローバル並列度を `Par::Seq` に固定。OLS/WLS/Logit/Probit/Tobit/2SLS/GMM の各 `fit()` と同じ）。理由・背景は `engine/src/linear/CLAUDE.md`「faerのグローバル並列度」と `.claude/rules/rust-style.md`「パフォーマンス」節を参照。FE は within 変換後に `OlsEstimator::fit` へ委譲するため OLS 側の呼び出しでも一応担保されるが、`cargo test -p engine` で `PanelEstimator::fit` を直接叩く経路との統一のため各 `fit()` からも呼ぶ。回帰ガード（`fit_pins_faer_global_parallelism_to_seq`）も他系統に倣って1本入れる。

## 設計上の決定（再発見コスト削減）

- **`engine` はpolars非依存。`panel-api-design.md` 6.1節の「polarsの`group_by`で実装」は`engine_pybind`層／抽出後配列の話**。`engine`側のグループ集約は、クラスター列と同じく `entity: &[String]`（長さ`n`、行はパネル観測順）を受け取る。
- **`quasi_demean_column` の内部集約は `HashMap` でよい（`cluster_cov_params` の `BTreeMap` 必須とは別）**。あるエンティティの和は観測順（入力行の固定順）に積まれ、各行の出力はそのエンティティの和だけに依存する。エンティティ「間」をまたぐ加算（`Σ_g S_g S_g'` のようにグループ順序が浮動小数点丸めに効く演算）が無いため反復順序非依存でビット単位決定的。`HashMap` で集約・引き当てが O(n log G) → O(n)。**クラスターロバスト分散等、グループ間加算があるパネル系の実装を今後書くときは `engine/src/linear/CLAUDE.md` の `BTreeMap` 方針に戻ること**。
- **`quasi_demean_column` は列単位の関数**（`y`/`x`をまとめて受けない）。呼び出し側（FE/REの`fit()`）が `y` と `x` の各列にループ適用し、変換後の列を `OlsEstimator::fit` に渡す（WLSがsqrt(w)変換データをOLSへ委譲するのと同型、4.3節・7.4節）。列ごとに独立な変換のため単体テストが単純になる。
- **θの渡し方は `&BTreeMap<String, f64>`（エンティティID→θ_i）**。観測単位の`&[f64]`や「エンティティ順の`&[f64]`」にしない（順序規約をFE/REと共有する必要が生じ、ミスの余地が残るため）。**FEはこの関数の `θ_i = 1.0`（全エンティティ）の特殊ケース**として扱う（`panel-api-design.md` 7.4節）。REは `θ_i = 1 - sqrt(σ_ε² / (T_i·σ_u² + σ_ε²))`（7.2節）。
- **`quasi_demean_column` はグループ平均（`ȳ_i.`）を返さない**（Issue #173スコープ外）。**`fixed_effects()`（6.6節、Issue #184）はこの関数を拡張せず実装済み**——`FeEstimator::fixed_effects()`は`fit()`が既に保持している`input`（変換前の元の`y`/`x`/`entity`/`time`）と`estimator().params()`から`slope_only_residual`/`group_residual_means`で都度再計算する（`quasi_demean_column`はwithin変換専用のまま据え置き）。σ_ε²再利用（7.4節、RE実装）で平均の保持が必要になったら、その時点で改めて検討する。
- **契約違反（`entity`と列の長さ不一致・`theta`のキー欠け）は`assert!`/`expect`でpanic**（`Result`を返さない）。ユーザー入力起因ではなく`engine_pybind`〜`engine`間の内部契約違反のため、`validate_cluster_groups`の`assert_eq!`と同じ扱い。`hausman_statistic`のshape契約（`beta_fe`/`beta_re`同長・`cov`が`k×k`）も同様に`assert!`。

- **`hausman_statistic` の設計（Issue #174、7.3節）**:
  - 入力は `beta_*: &[f64]` / `cov_*: &[Vec<f64>]`（`newton_step` と同じ形。RE呼び出し側が `Mat` から一度変換）。戻り値 `Result<(stat, df, p_value), CommonError>`。
  - **比較対象のalign（重なるスロープ係数のみ、REの切片・時間不変変数を除外）は呼び出し側（RE実装）の責務**。この関数は渡された `k` 個をそのまま使う。
  - 差行列 `Var(β_FE) - Var(β_RE)` は対称だが有限標本で非正定値になりうるため、Choleskyではなく `col_piv_qr` + `solve_lstsq`（`newton_step` と同じ相対閾値・NaN明示チェックの特異性検出）。
  - **統計量が負でもそのまま返す**（`plm::phtest` と同じ。`stat<=0` なら `p_value == 1.0`）。差行列が数値的に特異なときだけ `CommonError::ComputationFailed`。
  - **p値は `chi2.sf(stat)`（`1.0 - chi2.cdf(stat)` ではない）**。大きい `stat` で `cdf ≈ 1` になり小さいp値の相対精度が失われるのを避けるため（`sf` は正則化上側不完全ガンマを直接計算。`stat<=0` でも `1.0` を返すので負統計量の挙動は不変）。**`iv/gmm.rs` の Hansen J・Wald系は今も `1.0 - chi2.cdf` のまま**——一括で `sf` へ移行するかは別issue（このズレは意図的な暫定）。
  - `df` には常に `k` を使う。差行列の実効ランクが `k` 未満のとき `stat` と `df` に不整合が生じうる（`plm::phtest` も同じ制約）。
  - v1は classical Hausman のみ（`cov_type` 非依存）。robust版は将来issue。

## PanelError（Issue #172で確定済みの方針、変更時は要確認）

- FE/REで共有（`FeError`/`ReError`は作らない）。`CommonError` を `#[error(transparent)] Common(#[from] CommonError)` で包む（`LeastSquaresError`/`MleError`/`IvError` と同じ）。
- `WithinRegressionFailed { #[source] source: LeastSquaresError }` は `#[from]` を使わず明示的に `.map_err` で包む（`CommonError` が2経路で `PanelError` になる曖昧さを避けるため。`IvError::FirstStageFailed` と同じ判断）。
- RE固有バリアント（between回帰の自由度不足、Hausman統計量の非正定値ケース等）は未定義。RE実装issueで計算コードを書く過程で追加する（`common.rs` モジュールdocコメントの「追加候補」参照）。
