# Verification details

This page records how individual reference comparisons are set up, where a reference needed a workaround, and which statistics are compared against only one reference. The reference implementations, the statistics compared, the tolerances and the test data are on [Verification](verification.md).

## Notes on the cross-checks

These notes explain how particular reference comparisons are set up, and where a reference needed a workaround or differs from this package.

### IV: Wald statistic with cluster standard errors on `card`

With the nine regional clusters of the Wooldridge `card` example, the Wald (F) statistic differs from every reference by up to `1.7e-8` (2SLS) and `1.1e-8` (GMM), while all other statistics agree to `1e-10`.

An independent computation in 60-digit decimal arithmetic gives `F = 400.0460063`. `ivreg` is off by `6.7e-11`, linearmodels by `8.5e-10` and this package by `1.6e-8`, so the difference is this package's. The coefficients (`1e-14`) and standard errors (`1e-12`) are accurate, and the exact covariance matrix with this package's coefficients gives the exact `F`. The loss comes from the covariance matrix's relative error of about `3e-12`, amplified by the condition number of its slope block (about `3e7`; the squared experience variable has a much larger scale).

The tolerance for these two statistics on this example is therefore `5e-8`, about three times the largest measured difference. Improving the accuracy of the covariance computation is tracked separately.

### IV GMM cross-check with momentfit

`ivreg` has no GMM, so the independent reference for GMM is `momentfit`. A naive call does not match linearmodels or this package. The R script sets the following, and every GMM case (the synthetic scenarios, several weight × covariance combinations, multiple endogenous variables and the Wooldridge `card` data) then agrees to the [tolerance](verification.md#against-the-independent-cross-check):

- **Starting weight and centering.** The first step uses the 2SLS estimate (`initW = "tsls"`; the default is an identity weight) and the moment conditions are not centered, as in linearmodels.
- **HAC and cluster weights.** With these two weight types, the coefficients that `momentfit` 1.0 returns when it builds the weight itself differ from linearmodels' (for HAC by about `1e-2`). Reading its source suggests that the pivot of the pivoted Cholesky factor it stores is not applied, but that is not documented, so the cause is not claimed here. The script builds the weight matrix `S⁻¹` from `momentfit`'s own moment covariance and passes it explicitly, and then agrees with linearmodels.
- **HAC bandwidth.** `momentfit`'s `bw` is the denominator of the Bartlett kernel, so `bw = lags + 1`. Pre-whitening is switched off, and so is the `n/(n-q)` scaling of the moment covariance (it does not change the coefficients but it changes Hansen J).
- **Hansen J.** `momentfit` rebuilds the weight at the final estimate; here, as in linearmodels, the weight used in estimation is used.
- **Small-sample corrections.** Classical covariance: `momentfit` divides by `n - 1` after centering, this package by `n - k`, so the standard errors are rescaled by `√((n-1)/(n-k))`. Cluster covariance: linearmodels' factor is `G/(G-1) · (n-1)/(n-k)`, while `momentfit` applies only `G/(G-1)`, so the same rescaling is added. HC1 and HAC need no extra factor.

These factors are scalars applied in the script; the weight matrices, bread and meat matrices are computed by `momentfit`.

### IV without an intercept (`include_intercept=False`)

Four scenarios are fitted without a constant: the baseline, the just-identified case, a model with no exogenous regressors at all, and two endogenous variables. Each is fitted under classical, HC0, HC1 and HAC covariance, and GMM uses the classical weight.

- The baseline is also fitted with cluster standard errors, and (2SLS) with HC2 and HC3, which only `ivreg` provides.
- For GMM, the baseline additionally uses the robust, cluster and HAC weights (and the two-endogenous-variable case the robust weight). With the classical weight the point estimate equals 2SLS, and only these weights exercise the GMM-specific path.
- The references are linearmodels (formula without the constant `1`) and, independently, `ivreg` (`0 +` on both sides) for 2SLS and `momentfit` for GMM.
- Without a constant, R² is the uncentered one and the Wald statistic tests every coefficient.
- Cluster standard errors are compared with linearmodels for every statistic, and with `ivreg` and `momentfit`. For 2SLS the reference script recomputes the test statistics, p-values, confidence intervals and F statistic with `G - 1` degrees of freedom, as this package does.

Some reference behaviours differ here, so a few comparisons are left out:

- **`ivreg` cannot fit a model with no exogenous regressors and no constant** (it fails with `incorrect number of dimensions` when there is a single regressor), so that scenario is checked against linearmodels only.
- **`ivreg`'s Sargan statistic is not comparable without a constant.** It divides the auxiliary regression's sum of squares by the *centered* total sum of squares of the residuals, which assumes a constant among the instruments, and the statistic can become negative. It is not compared; Sargan is checked against linearmodels.
- **Hansen J differs from linearmodels for a classical weight and an over-identified model.** linearmodels always centers the residuals when it builds the classical weight (the robust, cluster and HAC weights are not centered, and their Hansen J agrees), this package (like `momentfit` and the 2SLS Sargan statistic) uses `e'e/n`. With a constant the mean residual is zero and the two agree; without one they do not (for the baseline scenario: 0.311 against 0.190). The Hansen J of these cases is therefore compared with `momentfit` only, not with linearmodels. Coefficients, standard errors, test statistics and the Wald statistic are compared with both.
- **`momentfit`** returns a point estimate that differs from 2SLS for an over-identified model without a constant (its `tsls()` and `initW = "tsls"`; the cause was not identified). The script computes the 2SLS estimate and the classical weight explicitly in that case. As a result the independence of this Hansen J is limited: `momentfit` only evaluates the statistic, and the 2SLS estimate and weight are computed in the script. It is backed by the identity that, for a classical weight, Hansen J equals the 2SLS Sargan statistic (which is compared with linearmodels).

### IV first stage

The first-stage regressions returned by `first_stage()` are compared with a direct `OLS` fit of the same regression (same regressors, `cov_type`, `include_intercept` and `confidence_level`), for 2SLS and GMM, with and without a constant, under classical, HC1, HAC and cluster covariance, and with several endogenous variables. No external reference is needed: the OLS itself is verified separately, and this checks the IV-specific wiring (which columns are passed, and how the constant is handled). It matters because a wrong constant setting leaves the coefficients and standard errors correct and changes only R², adjusted R², the F statistic and the degrees of freedom.

### FE and RE: cluster and Driscoll-Kraay standard errors

Point estimates and the classical and HC1 standard errors agree with linearmodels to machine precision. For `cov_type="cluster"` and `cov_type="dk"`, FE and RE deliberately use the small-sample corrections and degrees of freedom of fixest, Stata and plm rather than those of linearmodels (see [Inference conventions](inference-conventions.md#differences-from-other-packages)), so linearmodels is not a numerical reference for these two types. They are compared with R instead:

- FE against `fixest` with its default `ssc()`. Every statistic, including p-values and confidence intervals, agrees to machine precision.
- RE against `plm::vcovHC(method = "arellano", type = "sss")` for cluster and `plm::vcovSCC(type = "sss")` for Driscoll-Kraay.
- RE with a cluster column other than the entity against `lm` plus `sandwich::vcovCL` on plm's quasi-demeaned data, because plm can only cluster by entity or time.
- The Driscoll-Kraay bandwidth is passed to the reference explicitly, because neither fixest nor plm uses the same default rule.

plm's random-effects model reports z statistics, and its within model reports t statistics with `df.residual` degrees of freedom. The t statistics, p-values and confidence intervals are therefore recomputed from plm's standard errors with the degrees of freedom of this package (`G - 1` for cluster, `t_periods - 1` for Driscoll-Kraay).

**Second reference for FE.** FE cluster and Driscoll-Kraay have a second, independent reference built from `plm` (`model = "within"`) and `sandwich`, for one-way FE only (plm has no covariance matrix for two-way within models and can only cluster by entity or time). It agrees with the implementation and with fixest to machine precision on balanced and unbalanced panels, for every statistic including the F statistic (`plm::pwaldtest`). It is less independent than the table suggests:

- **Cluster:** plm supplies the within-transformed data and the coefficients. The standard error comes from `sandwich::vcovCL` on that data, so it is not a plm covariance estimator.
    - The small-sample factor is computed by `sandwich` rather than written by hand.
    - The count `K = k + 1` (the absorbed entity effect counted once, as in fixest's `K.fixef = "nonnested"`) is chosen in the reference script by adding an intercept. It is therefore the same convention as fixest and the implementation, not an independent one.
    - The `t` degrees of freedom (`G - 1`) are the same assumption.
- **Driscoll-Kraay:** plm's own `type = "sss"` correction counts the fixed effects differently from fixest, so it is not used. The raw Bartlett sandwich `plm::vcovSCC(type = "HC0")` is multiplied by fixest's factor `T / (T - 1) · (n - 1) / (n - k - G)`, written by hand in the reference script. plm therefore checks the kernel and bandwidth convention, not the correction factor, which only fixest verifies independently. The `t_periods - 1` degrees of freedom are again the same assumption.
- **Bandwidth equal to `t_periods - 1`:** with fixest 0.14.2, `vcov = DK(lag = t_periods - 1)` gives a standard error that equals the hand computation with lags 1 to `t_periods - 2` only (in a check with 12 entities and 6 periods and `lag = 5`: 0.08795), whereas this package, which includes the last lag of the standard Bartlett kernel, gives 0.08368. For smaller bandwidths fixest agrees with this package. The fixest documentation defines `lag` but does not state the maximum lag, so whether this is a definition or a defect was not determined. plm uses the standard Bartlett kernel and matches, so this boundary is checked against plm only.
- **Boundary cases:** the second reference also covers the cases fixest is checked on where a small count of clusters or periods makes the denominator degrees of freedom equal to the number of slopes: three clusters with two slopes, two clusters with one slope, and three periods with two slopes for Driscoll-Kraay. The case of fewer degrees of freedom than slopes is checked against fixest only.
    - Because plm clusters only by entity, the cluster counts are reached by keeping the first three or two entities rather than by an unrelated cluster column.
    - Unequal group sizes are represented, more mildly than for RE, by unequal numbers of observations per entity (2, 3, 5 and 10 periods in turn).
    - Driscoll-Kraay is also checked with explicit bandwidths (see below) and, for the boundary above, on balanced, unbalanced and four-period panels.
    - Within R² is compared with plm as well.

**Real data and explicit bandwidths.** On Wooldridge `wagepan` (`T = 8`, three regressors, so `T - 1 = 7` exceeds the number of tested coefficients), Driscoll-Kraay is compared for FE (one-way and two-way; fixest and plm for one-way) and for RE (plm). A bandwidth passed explicitly is compared too. The default rule `floor(4 (T / 100)^(2/9))` gives 2 for both `T = 6` and `T = 25`, which would otherwise leave the kernel weights barely exercised.

- FE: bandwidths 0, 1 and 3 (and 12 for the `T = 25` panel with a cross-sectionally correlated error) against fixest below `T - 1`, and the same values against plm. The scenarios are the baseline, unbalanced, autocorrelated and cross-sectionally correlated ones, with two-way effects on the balanced ones only.
- RE: bandwidths 0, 2 and 3 (and 12) against plm.

On the unbalanced panel plm's Swamy-Arora variance components differ from this package's. This moves plm's own RE estimates (coefficients by up to 0.2 %, standard errors by about 1 %, and, for Driscoll-Kraay at bandwidth 0, a confidence-interval bound close to zero by more than 10 %). It also moves the statistic of plm's own Hausman test by 1–2 %, which would hide the difference of about 2.1 % between bandwidths 2 and 3. The RE standard errors, inference statistics and Hausman test there, for every `cov_type` and every explicit bandwidth, are therefore compared with a reference built differently:

- The variance components of linearmodels' `RandomEffects` (which this package matches to machine precision) are handed to R, the data are quasi-demeaned with them, and plm's `vcov` (classical), `vcovHC` (HC1–HC3 and cluster) or `vcovSCC` (Driscoll-Kraay) is applied to the transformed data. Only the covariance estimator, the small-sample correction and the degrees of freedom are compared, at machine precision, which still detects a missing `G/(G-1)` factor (about 1.3 % in the cluster standard error).
- **Limits of this reference's independence.** plm supplies the coefficients and the covariance matrix. The variance components come from linearmodels (the primary reference, which checks them); the quasi-demeaning weights, the F statistic for the slopes alone (plm's `pwaldtest` would also test the transformed constant column), and the conversion to the t distribution (degrees of freedom `df_resid`, `G - 1` or `t_periods - 1` by `cov_type`) are written by hand. This reference is therefore less independent than a plm estimate: a misunderstanding shared by the hand-written parts and this package would not be caught by it.
- That the construction itself is right is checked every time the fixture is generated: handing plm's own variance components to it reproduces plm's own RE (every reported statistic) to a relative `1e-10`, for every `cov_type` and bandwidth, together with the t statistics, p-values, confidence intervals and the F-statistic p-value. This is what validates the weights, the F-statistic formula and the degrees of freedom of the t conversion.
- **The Hausman test** uses the same idea. `phtest(method = "aux")` builds its auxiliary regression from the weights plm computes internally. The reference therefore rebuilds the auxiliary regression from the given variance components (the quasi-demeaned response and regressors, the within-transformed regressors and a plain constant, as `phtest` does) and applies plm's covariance to it. The statistic is the Wald form for the within-transformed coefficients.
    - plm checks the auxiliary regression's coefficients and covariance matrix. The construction of the regression and the selection of the tested coefficients are written by hand.
    - Handing plm's own variance components to it reproduces `phtest` (statistic, p-value and degrees of freedom) to a relative `1e-10` for every `cov_type` and bandwidth each time the fixture is generated.

**Two-way FE with another cluster column.** For FE with two-way effects, clustering on a column other than the entity is compared with fixest in four cases:

- a column nested in the time effect (the second column of `effects`);
- a column nested in neither effect;
- the boundary of three clusters with two slopes (the denominator degrees of freedom equal the number of slopes);
- clusters of unequal size (2 to 50 observations).

**Boundary and failing inputs.** Driscoll-Kraay with `T = k + 1` periods for `k = 2` tested coefficients is compared with fixest and plm for FE and with plm for RE (standard errors and Hausman test). The 20-regressor, six-period panel is not compared for Driscoll-Kraay (FE) or for cluster and Driscoll-Kraay (RE); `fit()` raises `ValidationError` there, which is what the tests assert. For FE the covariance of the joint test of the slopes is structurally singular (the Driscoll-Kraay covariance has rank at most `T - 1`, below the 20 slopes). For RE the cause is the Hausman test's auxiliary regression: its 2k = 40 slopes are not fewer than the 40 clusters, and its 20 tested coefficients exceed `T - 1 = 5`.

**Degrees of freedom for RE.** plm reports z statistics, so the `G - 1` degrees of freedom for cluster are written by hand in the plm reference script. As an independent check, plm's quasi-demeaned data is passed to statsmodels `OLS(...).fit(cov_type="cluster", use_t=True)`, which computes the cluster standard errors, t statistics, p-values, confidence intervals, F statistic and the `G - 1` degrees of freedom natively. It agrees with the implementation to machine precision on balanced panels, including clusters defined by a column other than the entity (strongly unequal cluster sizes of 2 to 50 observations, and the minimal case of three clusters with one slope).

statsmodels cannot do the same for Driscoll-Kraay, because the inference degrees of freedom of its `hac-groupsum` are not `t_periods - 1`. The `t_periods - 1` degrees of freedom of RE Driscoll-Kraay therefore have no second reference: plm verifies the standard error only.

### FE and RE: F statistic

The F statistic tests that all slope coefficients are jointly zero (the constant and the fixed effects are not tested). FE and RE are checked against R for every `cov_type`, and the two methods are different:

- **FE** is a Wald test that follows `cov_type`, with `G - 1` denominator degrees of freedom for cluster and `t_periods - 1` for Driscoll-Kraay.
    - It is compared with `fixest::wald(keep = <slopes>, vcov = <same vcov>)` for classical, HC1, HC2, HC3, cluster and Driscoll-Kraay, one-way and two-way, and agrees to machine precision. `fixest::fitstat(m, "f")` is not used because it also tests the fixed-effect dummies.
    - The p-value is recomputed from the fixest statistic and the degrees of freedom of the t tests, because `wald()` raises the denominator degrees of freedom to at least the numerator degrees of freedom plus one. This only matters when the denominator degrees of freedom do not exceed the number of slope coefficients (`G - 1`, `t_periods - 1` or `df_resid` ≤ the number of slopes, for example two clusters with one slope, or one residual degree of freedom).
    - The boundaries `G = q + 1` and `t_periods = q + 1` with two slopes, and one residual degree of freedom with HC1–HC3, are included.
    - classical and HC1 are also compared with linearmodels.
    - For one-way FE with cluster and Driscoll-Kraay it is also compared with `plm::pwaldtest(test = "F", vcov = ...)` on the plm-based covariance matrix of the second reference (see above). The p-value uses the same hand-written denominator degrees of freedom (`G - 1`, `t_periods - 1`) as the t tests, and for Driscoll-Kraay the covariance matrix contains the hand-written correction factor.
- **RE** is the same Wald test as FE and also follows `cov_type` (denominator degrees of freedom `G - 1` for cluster, `t_periods - 1` for Driscoll-Kraay, `df_resid` otherwise).
    - Every `cov_type` is compared with the statistic of `plm::pwaldtest(test = "F", vcov = ...)`. Cluster on balanced panels is also compared with statsmodels `f_test` on plm's quasi-demeaned data (its `G - 1` denominator degrees of freedom are computed natively). classical and HC1 are also compared with linearmodels' `f_statistic_robust`.
    - All of them agree to machine precision on balanced panels, and linearmodels also on the unbalanced panel because the point estimates agree.
    - plm's own RE differs on the unbalanced panel because of the Swamy-Arora variance components (see above): by up to about 0.03 % for classical, 0.09 % for HC1 / HC2 / HC3, 0.13 % for cluster and 0.7 % for Driscoll-Kraay. The unbalanced panel is therefore compared with plm applied to data quasi-demeaned with linearmodels' variance components, at machine precision (see above).
    - The p-value is recomputed from the plm statistic and the degrees of freedom of the t tests, because `pwaldtest` only adjusts its denominator degrees of freedom when the covariance matrix carries a `cluster` attribute.
    - linearmodels' `f_statistic` is not used: it is based on the sums of squares of the transformed data and ignores `cov_type`, whereas the Wald form follows `cov_type` and cannot be negative.

## Not compared against a second reference

Where only one reference exists, or a reference differs in a documented way, the comparison is narrower than elsewhere. The cases are grouped by method.

### OLS

- **OLS Breusch-Pagan test with constant or duplicate variables.** statsmodels counts the chi-squared degrees of freedom of `het_breuschpagan` from the number of columns, not their rank. It is therefore given the variables that remain after the constant and duplicate columns are dropped. The dropping itself is checked against R, which is given the columns as they are and counts the rank.
- **OLS Breusch-Godfrey test without an intercept** is checked against R `lmtest::bgtest` only. statsmodels adds a constant to the auxiliary regression of a model without an intercept (R and Greene do not), so its value is a different statistic and is not used there.

### Logit and Probit

- **Probit and R's `glm`.** For a non-canonical link, R's `glm` covariance uses the expected information matrix, which differs from the observed information used here by 2–3 % (classical) and up to 8 % (HC0 / HC1). The cross-check therefore builds the observed-information covariance explicitly, checked against `numDeriv::hessian`. Logit is unaffected.
- **statsmodels gaps for Logit and Probit.** statsmodels 0.15.0 returns HC0 for `hc1` (no `n/(n-k)` correction) and has no `cov_type="opg"` (it raises `ValueError`), so the OPG covariance is built by hand from the model's `score_obs`. It cannot compute OPG marginal effects either, so R is the only reference for the OPG marginal effects and for `hc1`.
- **Logit and Probit without an intercept (`include_intercept=False`)** are checked against both statsmodels (classical, OPG, HC0 and cluster covariance; OPG marginal effects are not compared) and R (`glm` fitted with `- 1`, under classical, OPG, HC0, HC1 and cluster covariance, with balanced and imbalanced clusters, including the OPG marginal effects). R is the only reference for HC1 (see above) and for imbalanced clusters without an intercept (the statsmodels fixtures for the no-intercept case cover balanced clusters only). The cross-check uses the same tolerances as the fits with an intercept (measured up to about `1e-9` for Logit and `1e-8` for Probit). Without a constant the null model of the likelihood-ratio test is still the constant-only model, so the statistic can be negative.
- **Logit and Probit at a non-default confidence level (0.90)** are checked against both statsmodels (classical, OPG, HC0 and cluster covariance; OPG marginal effects are not compared) and R (also HC1, and the OPG marginal effects), for the coefficient intervals and the marginal-effect intervals. The two levels are set separately: `confidence_level` in the options for the coefficients and the argument of `marginal_effects()` for the marginal effects, which does not follow the options. R is the only reference for HC1 here too. The tolerances are those of the 0.95 fits.
- **Logit and Probit cluster count at the boundary.** With three slope coefficients, `G = 4` clusters (one more than the number of slopes, the smallest count that is accepted) is compared with statsmodels and R for every statistic, next to the balanced (10 clusters) and imbalanced (2 to 50 observations) cases. `G <= 3` is rejected before estimation, because the cluster covariance has rank at most `G - 1`; the tests check both `G = 2` and `G = 3`.
- **Logit and Probit classification table and predictions.** Against R, every fit (each covariance type, the cluster, no-intercept and confidence-level cases, and the real data) is compared on three things. The first is the classification table at the default threshold of 0.5 (an observation is classified as 1 when its probability is strictly above the threshold). The second is the first ten in-sample predicted probabilities and the sum over all rows, which catches an error in a later row. The third is the predicted probabilities for two new rows (each slope at its mean plus and minus one standard deviation), through both `predict()` and `augment()`. Against statsmodels, the classification table is compared in every case and `predict(new_data)` live, with and without an intercept. A threshold other than 0.5 has no external reference.
- **Logit and Probit `bfgs` / `lbfgs` combinations** (near-separation, cluster, real-data cluster) are compared with statsmodels' `newton` result only. R's `glm` does not depend on the solver and is already compared with this package's default `newton` on the same scenarios, so a solver-by-R comparison would only repeat the check that the solvers reach the same maximum, at the cross-check's tighter tolerance (`2e-7`, below the measured `bfgs` / `lbfgs` spread of up to `3.6e-6`). **Tobit `bfgs` / `lbfgs` on the real-data example** is checked against `AER::tobit` only, because `censReg` already differs from it by about `1e-4` on that data.

### Tobit

- **Tobit: both references are R packages.** Primary and cross-check are both R implementations (`survreg` and `maxLik`). The hand-written parts of the cross-check script (the Jacobian from log σ to σ, the HC1 correction, the marginal effects) are verified against numerical derivatives and an independent implementation of the closed-form expressions; the expected value among uncensored observations is also checked against numerical integration over the uncensored region and against the decomposition `E[y|x] = lower·P(lower) + upper·P(upper) + P(uncensored|x)·E[y|lower<y<upper,x]`. For that quantity, neither `AER::tobit` nor `censReg` has a counterpart, so predictions and marginal effects are also compared with `scipy.stats.truncnorm` (mean and variance of the truncated normal), fixed in the fixtures when they are generated; standard errors have no `scipy` counterpart.

### IV

- **IV 2SLS with cluster standard errors: the `G - 1` degrees of freedom.** `ivreg` and linearmodels report neither the t(`G - 1`) p-values and confidence intervals nor the F(`q`, `G - 1`) p-value of this package. The reference scripts compute them by hand from the reference's coefficients and standard errors (`G - 1` is written in both), so the choice of `G - 1` itself has no native second reference. The Wu-Hausman p-value is recomputed from `ivreg`'s statistic with `G - 1` degrees of freedom in the same way.
- **IV GMM** is checked against R `momentfit` for coefficients, standard errors, z statistics, p-values, confidence intervals, the robust Wald statistic and Hansen J. R², the weak-instrument F statistic, one-step GMM and iterated GMM are checked against linearmodels only (`momentfit` does not provide the first two, and its iteration stops under a different convergence rule). GMM with `hc2` / `hc3` has no reference at all: no such weight type was found in linearmodels 7.1 or `momentfit` 1.0 (the weight types used with `momentfit` here are `iid`, `MDS`, HAC and cluster). **IV (2SLS) HC2/HC3** is checked against `ivreg` only, because linearmodels has no equivalent.

### FE

- **FE:** AIC, BIC and log-likelihood are checked against fixest only (linearmodels does not provide them), and so are HC2 / HC3, two-way cluster and Driscoll-Kraay, cluster by a column other than the entity, and the two-way within R². One-way cluster and Driscoll-Kraay with entity clustering also have the plm reference described above, which is not a fully independent check of the small-sample correction for Driscoll-Kraay (linearmodels has no HC2 / HC3, uses different small-sample corrections for cluster and Driscoll-Kraay, and uses a different within R² definition for two-way FE). Between / overall R² are checked against linearmodels only.

### RE

- **The covariance matrix of the coefficients has no reference for four RE cases.** The cases are panels in which every entity has the same number of observations but at shifted time periods, with `variance_method` set to Wallace-Hussain or Amemiya (classical and cluster covariance).
    - `plm` (version 2.6.7) chooses its variance-component formulas by whether the panel is balanced, meaning every entity is observed in the same periods, not by whether the observation counts are equal. Here it uses the formulas for unbalanced panels, while this package uses the closed form for equal counts. The covariance matrix therefore differs.
    - `plm`'s matrix is not a reference for these cases. A matrix computed by hand from the closed form would use the same method as the estimator, so it would not be an independent check either.
    - The variance components of these cases are still compared; they are fixed to the closed form by the tests.
    - Every other stored covariance matrix is compared by a test, and the project's full test run in CI fails if a stored matrix is loaded but never compared.
- **RE with a time-invariant regressor:**
    - linearmodels 7.1 is not a reference, because it counts the time-invariant column in the degrees of freedom of the within regression. The variance component σ_ε² then differs from plm, which drops constant columns, and so do the coefficients from the fourth digit.
    - `plm::phtest(method = "aux")` is not used for the Hausman test either. With a time-invariant regressor, the statistic of plm 2.6.7 depends on the order of the regressors in the formula (in a simulated panel with two time-varying regressors and one time-invariant regressor: 76.5 and 41.0 for different orders), whereas the test should not.
    - The reference is the same auxiliary regression rebuilt from plm's transformed data, with the tested coefficients (those of the within-transformed regressors) selected by name. It agrees with `phtest` when no regressor is time-invariant.
    - Three checks are used, all to machine precision:
        - **A hand-written implementation of the specified procedure** (variance components from the within and between regressions, quasi-demeaning, the regression, and the Hausman auxiliary regression), with the covariance matrices computed by statsmodels `OLS` (classical, HC1–HC3, cluster) and by a Driscoll-Kraay written in numpy.
            - It is compared with this package for every statistic (coefficients, standard errors, t statistics, p-values, confidence intervals, F statistic and its degrees of freedom, log-likelihood, AIC, BIC, within / between / overall R², Hausman test) and every `cov_type`.
            - The panels are balanced and unbalanced ones, with one or several time-invariant regressors, time-invariant columns in any position, one time-varying regressor or all but one, and every regressor time-invariant (where plm fails with `empty model`, so this is the only reference).
            - Two sources of independence are limited: the variance components follow this package's definition (linearmodels', see below), and the Driscoll-Kraay formula is written from the same specification.
        - **plm on balanced panels** (the synthetic panel and Wooldridge `wagepan` with the time-invariant `educ`, `black` and `hisp` added, and with a year trend added): this package is compared with plm directly.
            - A regressor that varies over time only (a trend, an absolute year) has the same mean for every entity on a balanced panel. plm drops it from the between regression (it is collinear with the intercept), and so does this package (it is not counted in the between regression's degrees of freedom). The Hausman test then leaves out its within-transformed copy, which is not identified, and tests the remaining regressors.
            - On a panel with a row or two removed, the entity means differ, the column stays in both regressions and the two packages differ only through the variance component, as for any unbalanced panel.
            - Between and overall R² have no plm equivalent, so they are compared with the value computed from plm's coefficients by definition.
        - **plm on unbalanced panels:** plm and this package define the between-regression variance component σ_u² differently. A time-invariant coefficient is identified only by between-entity variation, so the difference is larger than for time-varying regressors (coefficients up to about 1.5 % on a mildly unbalanced panel and 13 % when the panel lengths range from 2 to 10 observations), and the two are not compared directly.
            - Instead, plm's own σ_ε² and σ_u² are given to the hand-written implementation, which then reproduces plm's coefficients, standard errors, t statistics, p-values, confidence intervals, F statistic and Hausman test, for every `cov_type`.
            - σ_ε² (which depends on the degrees of freedom `n - N - k_tv`) agrees with plm exactly.
- **Two-way RE** (two columns in `effects`, balanced panels): plm (`model = "random"`, `effect = "twoways"`, Swamy-Arora) is the only reference, so the checks lean on it more than elsewhere.
    - Against plm, every `cov_type` is compared for the coefficients, standard errors, F statistic, the three variance components (`ercomp`) and the three quasi-demeaning weights. The t statistics, p-values and confidence intervals are recomputed from plm's coefficients and standard errors with the t distribution (plm reports z statistics).
    - The Hausman test is plm's auxiliary regression rebuilt from plm's transformed data with the tested coefficients selected by name. With a regressor that varies in only one dimension, the statistic of `phtest(method = "aux")` in plm 2.6.7 differs from the rebuilt auxiliary regression (see the time-invariant case above); the two agree otherwise.
    - Log-likelihood, AIC, BIC and the within / between / overall R² are not computed by plm and are computed from plm's coefficients by definition in the reference script, so that part is not independent. As a second check, the log-likelihood, AIC and BIC are compared with statsmodels `OLS` fitted to plm's quasi-demeaned data.
    - A hand-written implementation of the specified procedure (variance components, the three-term quasi-demeaning, the regression, the Hausman auxiliary regression, the R², with statsmodels covariances and a numpy Driscoll-Kraay) is compared with this package for every statistic and `cov_type`, including inputs plm cannot fit (every regressor varies in one dimension only, where plm fails with `empty model`). Given plm's variance components, it also reproduces plm's coefficients, standard errors and Hausman test.
    - Cluster inference (t statistics, p-values, confidence intervals, F statistic and the `G - 1` denominator degrees of freedom) is compared with statsmodels `OLS(..., cov_type="cluster", use_t=True)` on plm's quasi-demeaned data, which computes them natively. The `t_periods - 1` degrees of freedom of Driscoll-Kraay have no second reference: plm reports z statistics, so they are the convention of the reference script and the hand-written implementation.
    - The default Driscoll-Kraay bandwidth is the value passed to plm, stored in the fixture. The between regressions drop a column whose unit means are constant (a regressor that varies across entities only in the time-means regression, and the other way round), as plm does.
    - Scenarios: a hand-built 6 × 4 panel, the synthetic panels listed under [Test data](verification.md#test-data), regressors varying in one dimension only (with every column order tried), an absolute-year column and `wagepan` with `educ` and a year trend.
- **`variance_method`** (Wallace-Hussain and Amemiya): plm (`random.method = "walhus"` and `"amemiya"`) is the only reference. The variance components, coefficients, standard errors, F statistic and Hausman test are compared with plm directly for these panels:
    - one-way balanced panels (including a time-invariant regressor, a regressor that varies only over time and a real-data panel);
    - unbalanced one-way panels (a mildly unbalanced one, one with 2 to 10 observations per entity, a nearly balanced one with two rows removed, and one with a time-invariant regressor);
    - panels without an entity effect or without a time effect (one-way balanced and unbalanced, two-way), where the estimated `σ_u²` or `σ_λ²` is negative and clipped to 0, so the weight is 0 and the GLS reduces to pooled OLS in that direction;
    - balanced two-way panels (small hand-built, regressors varying in one dimension, absolute year, real data).
    - **Correlated random effects** (a regressor together with its entity mean, and for two-way effects its time mean) are compared with plm in the same way, and the variance components, which follow from the rank of the between regressions, match plm. The scenarios are one-way balanced with Swamy-Arora and Wallace-Hussain, reordered columns, every time-varying regressor's mean added, unbalanced, with a time-invariant regressor, real data `wagepan` with the means of `married` and `union`, and two-way with entity means, time means and both. Swamy-Arora on an unbalanced panel with a mean column has only the hand-written reference, because plm estimates `σ_u²` differently there.
    - **The Hausman test** cannot be compared with `plm::phtest(method = "aux")` for these inputs, because its statistics in plm 2.6.7 depend on the order of the columns in the formula. The reference rebuilds plm's auxiliary regression and selects the coefficients by name, dropping the coefficients that `lm` reports as aliased (the same rule as this package). It is a hand-written computation from plm's parts, like the time-invariant case above.
    - **The aliasing tolerance.** The relative tolerance `1e-7` that decides whether a column is aliased is checked on both sides against plm's `lm`, with a column that differs from an entity mean by a relative `1e-3` (kept) and `1e-9` (dropped).
    - **Closed forms and trace-term forms.** The closed forms (plm's `dfcor = 1`, used on balanced panels) and the trace-term forms (`dfcor = 3`, used by plm on any unbalanced panel and reproduced here for unbalanced one-way panels) give different values on the same balanced panel, so the two cannot be checked against each other. One-way panels whose entities all have the same number of observations but different periods are the one input where this package and plm differ by design: this package uses the closed forms, and plm the trace-term forms because the panel is not balanced in plm's sense. The test pins both values to the hand-written closed form and trace-term form respectively and checks that they differ.
    - **The hand-written implementation** computes the variance components from plm's formulas with matrices expanded to one row per observation, independently of the entity-level computation of the package. The engine tests (`proptest`) compare the two on random unbalanced panels.
    - **Amemiya** is rejected for a regressor without within variation, which plm accepts on balanced panels. Those inputs have no plm reference, and only the rejection is tested (balanced and unbalanced one-way, several rejected columns, every regressor time-invariant, real data, two-way).
    - **The statsmodels checks** transform the data with plm's weights, so they test the log-likelihood, AIC, BIC and the cluster inference but not the variance components. The panel R² (within, between, overall) have no reference other than the hand-written implementation.
    - Swamy-Arora on an unbalanced one-way panel is not compared with plm (see above).
- **RE:** AIC, BIC and log-likelihood have no plm or linearmodels reference. Two-way RE compares them with statsmodels `OLS` on plm's quasi-demeaned data, while one-way RE relies on the OLS tests of the underlying computation.
    - HC2 / HC3, cluster, Driscoll-Kraay and the Hausman test (the regression-based version, compared with FE of the same structure as the RE model) are checked against plm only. On the unbalanced panel they are checked against plm applied to data quasi-demeaned with linearmodels' variance components, which is less independent (see above).
    - The cluster `G - 1` degrees of freedom are additionally checked against statsmodels, but the Driscoll-Kraay `t_periods - 1` degrees of freedom have no second reference.
    - Between / overall R² are checked against linearmodels only (plm has no equivalent).
