# Pythonレビュー

対応するCLAUDE.mdの方針: 2章（絶対に守るべき設計方針）、6章（コーディング規約）、7章（テスト方針）

## レビュー対象

$ARGUMENTS が指定されていればそのファイルを対象にする。指定がなければ `git diff` の変更内容を対象にする。

## チェック観点

1. **コーディング規約準拠**
   - 型ヒントが全public関数・クラスに付いているか
   - Googleスタイルdocstringが揃っているか
   - `ruff check` で違反がないか

2. **設計方針との整合性**
   - polars以外の入力（pandas等）を受け付ける実装になっていないか
   - formula文字列パース方式を導入していないか（List渡し＋オブジェクト渡しの原則が守られているか）
   - Arrowゼロコピーの原則を壊す不要なコピー・変換が発生していないか

3. **パフォーマンス・アーキテクチャ**
   - 大きなデータに対して非効率な処理（不要なループ、コピー等）がないか
   - 関数・クラスの責務が大きくなりすぎていないか（分割すべき箇所がないか）
   - 本来Rust側に持っていくべき計算処理がPython側に残っていないか

4. **テストの網羅性**
   - 対応するpyfixest/R比較テスト（`tests/api_tests/`）が用意されているか

## 出力形式

- 指摘事項を「規約」「設計方針」「パフォーマンス/アーキテクチャ」「テスト」の4カテゴリに分けてリストアップする。
- 各指摘に重要度（must fix / should fix / nice to have）を付ける。
- コードの修正はこのコマンドでは行わず、指摘のみ行う（修正は `/実装-python` に依頼する）。
