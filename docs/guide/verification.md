# Verification

Every estimator is compared numerically against established reference implementations before it is considered done. This page lists which implementations are used for each method, how closely the results must agree, and what is deliberately *not* compared against a reference.

## How verification works

- **Primary reference.** For each statistic a primary reference implementation is chosen, the one whose conventions match the ones used here. Results are compared at a relative tolerance of `1e-8` unless a documented reason requires a looser value.
- **Independent cross-check.** Where available, a second, independent implementation (mostly R) is compared as well. It covers the main reported statistics, not only coefficients and standard errors, so a bug in the primary reference or a shared misunderstanding is not silently inherited. Statistics without an independent reference are listed under [Not compared against a second reference](#not-compared-against-a-second-reference).
- **Frozen reference values.** Reference values are generated once from the pinned reference packages and stored as JSON files in the repository. The test suite compares against these files, so R and the reference packages are not needed to run the tests, and a new release of a reference package cannot change a result unnoticed.
- **Convention differences are documented.** When two implementations use different statistical conventions, such as small-sample corrections, the difference is documented (see [Inference conventions](inference-conventions.md)) and the comparison is adjusted for that statistic only.
- **Continuous integration.** The comparisons run on every pull request in the *CI (python)* workflow on Python 3.12, 3.13 and 3.14, and the Rust engine's own unit and property-based tests run in *CI (engine)*.

## Tolerances

Agreement is checked as `|ours - reference| <= max(rtol · |reference|, atol)`.

For the FE and RE cross-checks (coefficient and F-statistic p-values) the absolute floor `atol` is not applied: with a floor, a tail p-value below it (for example `1e-40`) would pass even if it were returned as `0`. FE p-values are compared by relative error only (`1e-6`, measured up to `3e-8` because the tail amplifies rounding errors in the statistic). RE p-values are compared the same way on balanced panels; on an unbalanced panel, where the statistics themselves differ by up to 0.7 % (see below), they are compared on the base-10 logarithm (within `0.1`, measured below `0.03`).

### IV GMM cross-check with momentfit

`ivreg` has no GMM, so the independent reference for GMM is `momentfit`. A naive call does not match linearmodels or this package. The R script sets the following, and every GMM case (ten synthetic scenarios, several weight × covariance combinations, multiple endogenous variables and the Wooldridge `card` data) then agrees to the tolerance above:

- **Starting weight and centering.** The first step uses the 2SLS estimate (`initW = "tsls"`; the default is an identity weight) and the moment conditions are not centered, as in linearmodels.
- **HAC and cluster weights.** `momentfit` 1.0 loses the pivot of the pivoted Cholesky factor it stores for these two weight types, which makes the coefficients wrong (HAC by about `1e-2`). The script therefore builds the weight matrix `S⁻¹` from `momentfit`'s own moment covariance and passes it explicitly.
- **HAC bandwidth.** `momentfit`'s `bw` is the denominator of the Bartlett kernel, so `bw = lags + 1`. Pre-whitening is switched off, and so is the `n/(n-q)` scaling of the moment covariance (it does not change the coefficients but it changes Hansen J).
- **Hansen J.** `momentfit` rebuilds the weight at the final estimate; here, as in linearmodels, the weight used in estimation is used.
- **Small-sample corrections.** Classical covariance: `momentfit` divides by `n - 1` after centering, this package by `n - k`, so the standard errors are rescaled by `√((n-1)/(n-k))`. Cluster covariance: linearmodels' factor is `G/(G-1) · (n-1)/(n-k)`, while `momentfit` applies only `G/(G-1)`, so the same rescaling is added. HC1 and HAC need no extra factor.

These factors are scalars applied in the script; the weight matrices, bread and meat matrices are computed by `momentfit`.

### IV without an intercept (`include_intercept=False`)

Four scenarios are fitted without a constant (the baseline, the just-identified case, a model with no exogenous regressors at all, and two endogenous variables), each under classical, HC0, HC1 and HAC covariance; GMM uses the classical weight. The baseline is also fitted with cluster standard errors, and (2SLS) with HC2 and HC3, which only `ivreg` provides. For GMM, the baseline additionally uses the robust, cluster and HAC weights (and the two-endogenous-variable case the robust weight), because with the classical weight the point estimate equals 2SLS and only these weights exercise the GMM-specific path. The references are linearmodels (formula without the constant `1`) and, independently, `ivreg` (`0 +` on both sides) for 2SLS and `momentfit` for GMM. Without a constant, R² is the uncentered one and the Wald statistic tests every coefficient. Cluster standard errors are compared with linearmodels for coefficients and standard errors only (as with a constant, its test statistics use `df_resid` while this package uses `G - 1`); the other statistics come from `ivreg` and `momentfit`. Some reference behaviours differ here, so a few comparisons are left out:

- **`ivreg` cannot fit a model with no exogenous regressors and no constant** (it fails with `incorrect number of dimensions` when there is a single regressor), so that scenario is checked against linearmodels only.
- **`ivreg`'s Sargan statistic is not comparable without a constant.** It divides the auxiliary regression's sum of squares by the *centered* total sum of squares of the residuals, which assumes a constant among the instruments, and the statistic can become negative. It is not compared; Sargan is checked against linearmodels.
- **Hansen J differs from linearmodels for a classical weight and an over-identified model.** linearmodels always centers the residuals when it builds the classical weight (the robust, cluster and HAC weights are not centered, and their Hansen J agrees), this package (like `momentfit` and the 2SLS Sargan statistic) uses `e'e/n`. With a constant the mean residual is zero and the two agree; without one they do not (for the baseline scenario: 0.311 against 0.190). The Hansen J of these cases is therefore compared with `momentfit` only, not with linearmodels. Coefficients, standard errors, test statistics and the Wald statistic are compared with both.
- **`momentfit`** returns a point estimate that differs from 2SLS for an over-identified model without a constant (its `tsls()` and `initW = "tsls"`; the cause was not identified). The script computes the 2SLS estimate and the classical weight explicitly in that case. As a result the independence of this Hansen J is limited: `momentfit` only evaluates the statistic, and the 2SLS estimate and weight are computed in the script. It is backed by the identity that, for a classical weight, Hansen J equals the 2SLS Sargan statistic (which is compared with linearmodels).

### IV first stage

The first-stage regressions returned by `first_stage()` are compared with a direct `OLS` fit of the same regression (same regressors, `cov_type`, `include_intercept` and `confidence_level`), for 2SLS and GMM, with and without a constant, under classical, HC1, HAC and cluster covariance, and with several endogenous variables. No external reference is needed: the OLS itself is verified separately, and this checks the IV-specific wiring (which columns are passed, and how the constant is handled). It matters because a wrong constant setting leaves the coefficients and standard errors correct and changes only R², adjusted R², the F statistic and the degrees of freedom.

### FE and RE: cluster and Driscoll–Kraay standard errors

Point estimates and the classical and HC1 standard errors agree with linearmodels to machine precision. For `cov_type="cluster"` and `cov_type="dk"`, FE and RE deliberately use the small-sample corrections and degrees of freedom of fixest, Stata and plm rather than those of linearmodels (see [Inference conventions](inference-conventions.md#differences-from-other-packages)), so linearmodels is not a numerical reference for these two types. They are compared with R instead: FE against `fixest` with its default `ssc()` (every statistic, including p-values and confidence intervals, agrees to machine precision), RE against `plm::vcovHC(method = "arellano", type = "sss")` for cluster and `plm::vcovSCC(type = "sss")` for Driscoll–Kraay. RE with a cluster column other than the entity is compared against `lm` plus `sandwich::vcovCL` on plm's quasi-demeaned data, because plm can only cluster by entity or time. The Driscoll–Kraay bandwidth is passed to the reference explicitly, because neither fixest nor plm uses the same default rule. plm reports z statistics, so its t statistics, p-values and confidence intervals are recomputed from its standard errors with the t distribution (`G - 1` degrees of freedom for cluster, `t_periods - 1` for Driscoll–Kraay).

**Second reference for FE.** FE cluster and Driscoll–Kraay have a second, independent reference built from `plm` (`model = "within"`) and `sandwich`, for one-way FE only (plm has no covariance matrix for two-way within models and can only cluster by entity or time). It agrees with the implementation and with fixest to machine precision on balanced and unbalanced panels, for every statistic including the F statistic (`plm::pwaldtest`). It is less independent than the table suggests:

- **Cluster:** plm supplies the within-transformed data and the coefficients; the standard error comes from `sandwich::vcovCL` on that data, so it is not a plm covariance estimator. The small-sample factor is computed by `sandwich` rather than written by hand, but the count `K = k + 1` (the absorbed entity effect counted once, as in fixest's `K.fixef = "nonnested"`) is chosen in the reference script by adding an intercept, so it is the same convention as fixest and the implementation, not an independent one. The `t` degrees of freedom (`G - 1`) are the same assumption.
- **Driscoll–Kraay:** plm's own `type = "sss"` correction counts the fixed effects differently from fixest, so it is not used. The raw Bartlett sandwich `plm::vcovSCC(type = "HC0")` is multiplied by fixest's factor `T / (T - 1) · (n - 1) / (n - k - G)`, written by hand in the reference script. plm therefore checks the kernel and bandwidth convention, not the correction factor, which only fixest verifies independently. The `t_periods - 1` degrees of freedom are again the same assumption.
- **Bandwidth equal to `t_periods - 1`:** fixest drops the last lag term at this boundary, so it does not match the implementation, which keeps the standard Bartlett kernel. The cause is an off-by-one in fixest's compiled routine `cpp_driscoll_kraay`: it caps the number of lag terms (including lag 0) at `T - 1`, which truncates the maximum lag to `T - 2` only when the bandwidth is `T - 1`. For smaller bandwidths fixest agrees with the implementation. plm uses the standard Bartlett kernel and matches, so this boundary is checked against plm only.
- **Boundary cases:** the second reference also covers the cases fixest is checked on where a small count of clusters or periods makes the denominator degrees of freedom equal to the number of slopes (the case of fewer degrees of freedom than slopes is checked against fixest only): three clusters with two slopes, two clusters with one slope, and three periods with two slopes for Driscoll–Kraay. Because plm clusters only by entity, the cluster counts are reached by keeping the first three or two entities rather than by an unrelated cluster column, and unequal group sizes are represented, more mildly than for RE, by unequal numbers of observations per entity (2, 3, 5 and 10 periods in turn). Driscoll–Kraay is also checked with bandwidths 0 and 1 and, for the boundary above, on balanced, unbalanced and four-period panels. Within R² is compared with plm as well.

**Degrees of freedom for RE.** plm reports z statistics, so the `G - 1` degrees of freedom for cluster are written by hand in the plm reference script. As an independent check, plm's quasi-demeaned data is passed to statsmodels `OLS(...).fit(cov_type="cluster", use_t=True)`, which computes the cluster standard errors, t statistics, p-values, confidence intervals, F statistic and the `G - 1` degrees of freedom natively. It agrees with the implementation to machine precision on balanced panels, including clusters defined by a column other than the entity (strongly unequal cluster sizes of 2 to 50 observations, and the minimal case of three clusters with one slope). statsmodels cannot do the same for Driscoll–Kraay (its `hac-groupsum` inference degrees of freedom are not `t_periods - 1`), so the `t_periods - 1` degrees of freedom of RE Driscoll–Kraay have no second reference: plm verifies the standard error only.

### FE and RE: F statistic

The F statistic tests that all slope coefficients are jointly zero (the constant and the fixed effects are not tested). FE and RE are checked against R for every `cov_type`, and the two methods are different:

- **FE** is a Wald test that follows `cov_type`, with `G - 1` denominator degrees of freedom for cluster and `t_periods - 1` for Driscoll–Kraay. It is compared with `fixest::wald(keep = <slopes>, vcov = <same vcov>)` for classical, HC1, HC2, HC3, cluster and Driscoll–Kraay, one-way and two-way, and agrees to machine precision. `fixest::fitstat(m, "f")` is not used because it also tests the fixed-effect dummies. The p-value is recomputed from the fixest statistic and the degrees of freedom of the t tests, because `wald()` raises the denominator degrees of freedom to at least the numerator degrees of freedom plus one (this only matters when the denominator degrees of freedom do not exceed the number of slope coefficients: `G - 1`, `t_periods - 1` or `df_resid` ≤ the number of slopes, e.g. two clusters with one slope, or one residual degree of freedom). The boundaries `G = q + 1` and `t_periods = q + 1` with two slopes, and one residual degree of freedom with HC1–HC3, are included. classical and HC1 are also compared with linearmodels. For one-way FE with cluster and Driscoll–Kraay it is also compared with `plm::pwaldtest(test = "F", vcov = ...)` on the plm-based covariance matrix of the second reference (see above); the p-value uses the same hand-written denominator degrees of freedom (`G - 1`, `t_periods - 1`) as the t tests, and for Driscoll–Kraay the covariance matrix contains the hand-written correction factor.
- **RE** is the same Wald test as FE and also follows `cov_type` (denominator degrees of freedom `G - 1` for cluster, `t_periods - 1` for Driscoll–Kraay, `df_resid` otherwise). Every `cov_type` is compared with the statistic of `plm::pwaldtest(test = "F", vcov = ...)`, and cluster on balanced panels also with statsmodels `f_test` on plm's quasi-demeaned data (its `G - 1` denominator degrees of freedom are computed natively); classical and HC1 are also compared with linearmodels' `f_statistic_robust`. Both agree to machine precision on balanced panels, and linearmodels also on the unbalanced panel because the point estimates agree. plm differs on the unbalanced panel because of the Swamy–Arora variance components (see above): by up to about 0.03 % for classical, 0.09 % for HC1 / HC2 / HC3, 0.13 % for cluster and 0.7 % for Driscoll–Kraay. The p-value is recomputed from the plm statistic and the degrees of freedom of the t tests, because `pwaldtest` only adjusts its denominator degrees of freedom when the covariance matrix carries a `cluster` attribute. linearmodels' `f_statistic` is not used: it is based on the sums of squares of the transformed data, ignores `cov_type` and can be **negative** for very unbalanced panels, while the Wald form cannot.

## Not compared against a second reference

- **Tobit: both references are R packages.** Primary and cross-check are both R implementations (`survreg` and `maxLik`). The hand-written parts of the cross-check script (the Jacobian from log σ to σ, the HC1 correction, the marginal effects) are verified against numerical derivatives and an independent implementation of the closed-form expressions; the expected value among uncensored observations is also checked against numerical integration over the uncensored region and against the decomposition `E[y|x] = lower·P(lower) + upper·P(upper) + P(uncensored|x)·E[y|lower<y<upper,x]`. For that quantity, neither `AER::tobit` nor `censReg` has a counterpart, so predictions and marginal effects are also compared with `scipy.stats.truncnorm` (mean and variance of the truncated normal), fixed in the fixtures when they are generated; standard errors have no `scipy` counterpart.
- **Probit and R's `glm`.** For a non-canonical link, R's `glm` covariance uses the expected information matrix, which differs from the observed information used here by 2–3 % (classical) and up to 8 % (HC0 / HC1). The cross-check therefore builds the observed-information covariance explicitly, checked against `numDeriv::hessian`. Logit is unaffected.
- **statsmodels gaps for Logit and Probit.** statsmodels returns HC0 for `hc1` (no `n/(n-k)` correction) and cannot compute OPG marginal effects, so R is the only reference for those two.
- **Logit and Probit `bfgs` / `lbfgs` combinations** (near-separation, cluster, real-data cluster) are compared with statsmodels' `newton` result only. R's `glm` does not depend on the solver and is already compared with this package's default `newton` on the same scenarios, so a solver-by-R comparison would only repeat the check that the solvers reach the same maximum, at the cross-check's tighter tolerance (`1e-6`, below the measured `bfgs` / `lbfgs` spread of up to `3.6e-6`). **Tobit `bfgs` / `lbfgs` on the real-data example** is checked against `AER::tobit` only, because `censReg` already differs from it by about `1e-4` on that data.
- **IV GMM** is checked against R `momentfit` for coefficients, standard errors, z statistics, p-values, confidence intervals, the robust Wald statistic and Hansen J. R², the weak-instrument F statistic, one-step GMM and iterated GMM are checked against linearmodels only (`momentfit` does not provide the first two, and its iteration stops under a different convergence rule). GMM with `hc2` / `hc3` has no reference at all, because neither linearmodels nor `momentfit` implements it. **IV (2SLS) HC2/HC3** is checked against `ivreg` only, because linearmodels has no equivalent.
- **FE:** AIC, BIC and log-likelihood are checked against fixest only (linearmodels does not provide them), and so are HC2 / HC3, two-way cluster and Driscoll–Kraay, cluster by a column other than the entity, and the two-way within R². One-way cluster and Driscoll–Kraay with entity clustering also have the plm reference described above, which is not a fully independent check of the small-sample correction for Driscoll–Kraay (linearmodels has no HC2 / HC3, uses different small-sample corrections for cluster and Driscoll–Kraay, and uses a different within R² definition for two-way FE). Between / overall R² are checked against linearmodels only.
- **RE with a time-invariant regressor:** linearmodels is not a reference, because it counts the time-invariant column in the degrees of freedom of the within regression (the variance component σ_ε² differs from plm, which drops constant columns, and so do the coefficients from the fourth digit). `plm::phtest(method = "aux")` cannot be used for the Hausman test either, because it selects the tested coefficients by position and, with a time-invariant regressor, tests the coefficients of the quasi-demeaned regressors instead of the within-transformed ones; the reference is the same auxiliary regression rebuilt from plm's transformed data with the tested coefficients selected by name (it agrees with `phtest` when no regressor is time-invariant). Three checks are used, all to machine precision:
  - **A hand-written implementation of the specified procedure** (variance components from the within and between regressions, quasi-demeaning, the regression, and the Hausman auxiliary regression), with the covariance matrices computed by statsmodels `OLS` (classical, HC1–HC3, cluster) and by a Driscoll–Kraay written in numpy. It is compared with this package for every statistic (coefficients, standard errors, t statistics, p-values, confidence intervals, F statistic and its degrees of freedom, log-likelihood, AIC, BIC, within / between / overall R², Hausman test) and every `cov_type`, on balanced and unbalanced panels, with one or several time-invariant regressors, time-invariant columns in any position, one time-varying regressor or all but one, and every regressor time-invariant (where plm fails with `empty model`, so this is the only reference). Two sources of independence are limited: the variance components follow this package's definition (linearmodels', see below), and the Driscoll–Kraay formula is written from the same specification.
  - **plm on balanced panels** (the synthetic panel and Wooldridge `wagepan` with the time-invariant `educ`, `black` and `hisp` added, and with a year trend added): this package is compared with plm directly. A regressor that varies over time only (a trend, an absolute year) has the same mean for every entity on a balanced panel, so plm drops it from the between regression (it is collinear with the intercept) and so does this package (it is not counted in the between regression's degrees of freedom); the Hausman test then leaves out its within-transformed copy, which is not identified, and tests the remaining regressors. On a panel with a row or two removed, the entity means differ, the column stays in both regressions and the two packages differ only through the variance component, as for any unbalanced panel. Between and overall R² have no plm equivalent, so they are compared with the value computed from plm's coefficients by definition.
  - **plm on unbalanced panels:** plm and this package define the between-regression variance component σ_u² differently, and a time-invariant coefficient is identified only by between-entity variation, so the difference is larger than for time-varying regressors (coefficients up to about 1.5 % on a mildly unbalanced panel and 13 % when the panel lengths range from 2 to 10 observations), and the two are not compared directly. Instead, plm's own σ_ε² and σ_u² are given to the hand-written implementation, which then reproduces plm's coefficients, standard errors, t statistics, p-values, confidence intervals, F statistic and Hausman test, for every `cov_type`. σ_ε² (which depends on the degrees of freedom `n - N - k_tv`) agrees with plm exactly.
- **Two-way RE** (`REOptions.time`, balanced panels): plm (`model = "random"`, `effect = "twoways"`, Swamy–Arora) is the only reference, so the checks lean on it more than elsewhere. Against plm, every `cov_type` is compared for the coefficients, standard errors, F statistic, the three variance components (`ercomp`) and the three quasi-demeaning weights. The t statistics, p-values and confidence intervals are recomputed from plm's coefficients and standard errors with the t distribution (plm reports z statistics). The Hausman test is plm's auxiliary regression rebuilt from plm's transformed data with the tested coefficients selected by name, because `phtest(method = "aux")` picks the wrong coefficients when a regressor varies in only one dimension; it agrees with `phtest` otherwise. Log-likelihood, AIC, BIC and the within / between / overall R² are not computed by plm and are computed from plm's coefficients by definition in the reference script, so that part is not independent; as a second check, the log-likelihood, AIC and BIC are compared with statsmodels `OLS` fitted to plm's quasi-demeaned data. A hand-written implementation of the specified procedure (variance components, the three-term quasi-demeaning, the regression, the Hausman auxiliary regression, the R², with statsmodels covariances and a numpy Driscoll–Kraay) is compared with this package for every statistic and `cov_type`, including inputs plm cannot fit (every regressor varies in one dimension only, where plm fails with `empty model`). Given plm's variance components, the hand-written implementation also reproduces plm's coefficients, standard errors and Hausman test. Cluster inference (t statistics, p-values, confidence intervals, F statistic and the `G - 1` denominator degrees of freedom) is compared with statsmodels `OLS(..., cov_type="cluster", use_t=True)` on plm's quasi-demeaned data, which computes them natively; the `t_periods - 1` degrees of freedom of Driscoll–Kraay have no second reference (plm reports z statistics, so they are the convention of the reference script and the hand-written implementation). The default Driscoll–Kraay bandwidth is the value passed to plm, stored in the fixture. The between regressions drop a column whose unit means are constant (a regressor that varies across entities only in the time-means regression, and the other way round), as plm does. Scenarios: a hand-built 6 × 4 panel, the synthetic panels listed above, regressors varying in one dimension only (with every column order tried), an absolute-year column and `wagepan` with `educ` and a year trend.
- **`variance_method`** (Wallace-Hussain and Amemiya): plm (`random.method = "walhus"` and `"amemiya"`) is the only reference, so the variance components, coefficients, standard errors, F statistic and Hausman test are compared with plm directly, for one-way balanced panels (including a time-invariant regressor, a regressor that varies only over time and a real-data panel), unbalanced one-way panels (a mildly unbalanced one, one with 2 to 10 observations per entity, a nearly balanced one with two rows removed, and one with a time-invariant regressor), panels without an entity effect or without a time effect (the estimated `σ_u²` or `σ_λ²` is negative and clipped to 0, so the weight is 0 and the GLS reduces to pooled OLS in that direction; one-way balanced and unbalanced, two-way) and balanced two-way panels (small hand-built, regressors varying in one dimension, absolute year, real data). Correlated random effects (a regressor together with its entity mean, and for two-way effects its time mean; one-way balanced with Swamy-Arora and Wallace-Hussain, reordered columns, every time-varying regressor's mean added, unbalanced, with a time-invariant regressor, real data `wagepan` with the means of `married` and `union`; two-way with entity means, time means and both) is compared with plm in the same way: the variance components, which follow from the rank of the between regressions, match plm. The Hausman test cannot be compared with `plm::phtest(method = "aux")` here, because that function selects the tested coefficients by position and returns statistics that depend on the order of the columns in the formula; the reference rebuilds plm's auxiliary regression and selects the coefficients by name, dropping the coefficients that `lm` reports as aliased (the same rule as this package), so it is a hand-written computation from plm's parts, like the time-invariant case above. Swamy-Arora on an unbalanced panel with a mean column has only the hand-written reference (plm estimates `σ_u²` differently there). The relative tolerance `1e-7` that decides whether a column is aliased is checked on both sides against plm's `lm` with a column that differs from an entity mean by a relative `1e-3` (kept) and `1e-9` (dropped). The closed forms (plm's `dfcor = 1`, used on balanced panels) and the trace-term forms (`dfcor = 3`, used by plm on any unbalanced panel and reproduced here for unbalanced one-way panels) give different values on the same balanced panel, so the two cannot be checked against each other. One-way panels whose entities all have the same number of observations but different periods are the one input where this package and plm differ by design (this package uses the closed forms, plm the trace-term forms because the panel is not balanced in plm's sense); the test pins both values to the hand-written closed form and trace-term form respectively and checks that they differ. The hand-written implementation computes the variance components from plm's formulas with matrices expanded to one row per observation, independently of the entity-level computation of the package, and the engine tests (`proptest`) compare the two on random unbalanced panels. Amemiya is rejected for a regressor without within variation, which plm accepts on balanced panels, so those inputs have no plm reference and only the rejection is tested (balanced and unbalanced one-way, several rejected columns, every regressor time-invariant, real data, two-way). The statsmodels checks transform the data with plm's weights, so they test the log-likelihood, AIC, BIC and the cluster inference but not the variance components; the panel R² (within, between, overall) have no reference other than the hand-written implementation. Swamy-Arora on an unbalanced one-way panel is not compared with plm (see above).
- **RE:** AIC, BIC and log-likelihood have no plm or linearmodels reference; two-way RE compares them with statsmodels `OLS` on plm's quasi-demeaned data, while one-way RE relies on the OLS tests of the underlying computation. HC2 / HC3, cluster, Driscoll–Kraay and the Hausman test (the regression-based version, compared with FE of the same structure as the RE model) are checked against plm only; the cluster `G - 1` degrees of freedom are additionally checked against statsmodels, but the Driscoll–Kraay `t_periods - 1` degrees of freedom have no second reference. Between / overall R² are checked against linearmodels only (plm has no equivalent).

- **OLS Breusch-Pagan test with constant or duplicate variables.** statsmodels counts the chi-squared degrees of freedom of `het_breuschpagan` from the number of columns, not their rank, so it is given the variables that remain after the constant and duplicate columns are dropped; the dropping itself is checked against R, which is given the columns as they are and counts the rank.
- **OLS Breusch-Godfrey test without an intercept** is checked against R `lmtest::bgtest` only. statsmodels adds a constant to the auxiliary regression of a model without an intercept (R and Greene do not), so its value is a different statistic and is not used there.

## Test data

All synthetic datasets are generated once, frozen as CSV files in the repository and read from there, so a later change to a data generator cannot silently invalidate stored reference values.

**Synthetic scenarios** (not every scenario applies to every method):

- small samples, including the boundary of exactly one residual degree of freedom
- large error variance, heteroskedasticity, autocorrelation (HAC)
- moderate multicollinearity, ill-conditioned designs (variables on very different scales, correlations above 0.99)
- many regressors (`k = 20`), regressors with heavy-tailed outliers
- cluster structures with equal group sizes, strongly unequal group sizes (for example 2, 3, 5, 10, 30, 50) and the minimum number of clusters
- censoring patterns (light, moderate, heavy, right-censored, interval-censored, and interval-censored with a narrow uncensored interval so that observations fall in both tails) for Tobit; weak and multiple instruments for IV; unbalanced panels and cross-sectional dependence for FE / RE
- time-invariant regressors for RE: one, or several (a continuous and a dummy), on a balanced panel and on unbalanced panels, including panel lengths from 2 to 10 observations per entity
- regressors that vary in only one dimension for RE: a regressor that varies over time only (a trend or an absolute year, which one-way RE drops from the between regression) and one that varies across entities only, on balanced panels with five periods, with the column in any position, on a nearly balanced panel (two rows removed) and with every regressor one-dimensional; two-way RE on panels from 5×4 to 15×25, with unequal variance, serial correlation and strongly unequal scales

**Real data** (textbook datasets from the `wooldridge` package, loaded at test time and compared with the references only):

| Method | Dataset |
|---|---|
| OLS | `wage1`, `gpa2` (the White test also uses `wage1` with the dummies `female` and `married`, with the squared terms `expersq` and `tenursq`, and with the mutually exclusive region dummies `northcen`, `south` and `west`, so that terms of its auxiliary regression are duplicated or constant; the Breusch-Pagan test uses `hprice1` (its LM and F statistics are also compared with the values printed in Wooldridge's Example 8.4), `wage1`, and `wage1` with columns that are not in the model as the variables; the Breusch-Godfrey test also uses the time series `phillips`, with the rows shuffled and ordered by `year`) |
| WLS | `401ksubs` |
| Logit, Probit, Tobit | `mroz` |
| Logit, Probit (cluster standard errors with many clusters) | `apple` (`y = ecolbs > 0`, clustered by `state`: 49 clusters of 1 to 66 observations) |
| IV | `card` |
| FE, RE | `wagepan` (RE also with the time-invariant `educ`, `black` and `hisp` added, and with a year trend `yr` added; two-way RE with `educ` and `yr`) |

**Error paths.** Invalid input (missing values, duplicate columns, too few observations, too few clusters, out-of-range options) must raise a validation error, and numerical failure (for example perfect multicollinearity, complete or quasi-complete separation) must raise a computation error. Only the exception type is checked, with no reference values: most reference packages silently drop the offending columns and continue, which this package deliberately does not do.

## Rust engine tests

The computational core has its own unit tests (`cargo test`) and property-based tests (`proptest`) for the estimators. The property tests check invariants such as scale and permutation invariance across randomly generated inputs, which a fixed set of scenarios cannot cover.

## Reproducing

The reference values are produced by the scripts under `benchmark/` and regenerated with `benchmark/regenerate_all.py`; the generating R and Python packages are pinned. See the [repository](https://github.com/masahiroyecon1997dev/econometricsmodels) for the scripts and the stored reference values under `tests/fixtures/benchmarks/`.
