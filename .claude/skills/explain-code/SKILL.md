# コード解説

対応するCLAUDE.mdの方針: 14章（判断が分かれる点は都度確認）、15章（大量ファイル調査はサブエージェントに委譲）

このスキルは**ユーザー自身への説明（対話）が目的**で、コード自体は変更しない。
リファクタリング候補の洗い出し・Issue起票は`.claude/skills/refactor-candidates`、
実施は`.claude/skills/refactor`に委ねる。

## 対象

$ARGUMENTS

範囲が曖昧な場合（ファイルは指定されたが関数名までは無い等）は、ファイル全体を対象にしてよい。
対象が存在しない・複数解釈できる場合は着手前にユーザーへ確認する。

## 解説方針

1. **プログラミング初心者向けの丁寧さ**
   対象ファイルの言語（Rust / Python / R）ごとの構文・イディオムも、知っている前提を置かずに
   説明する（例: Rustなら所有権・`Result`/`?`演算子・トレイト境界、Pythonなら型ヒント・
   デコレータ・内包表記、Rなら`<-`代入・ベクトル化演算等、対象コードに出てくるものだけでよい。
   出てこない構文まで先回りして説明しない）。
   「何をしているか」だけでなく「なぜそう書くのか」（言語の慣習・このコードでの必然性）も触れる。

2. **長いコードは区切って解説**
   ファイル全体を一度に読ませるのではなく、意味のあるまとまり（関数単位・処理ブロック単位）に
   区切り、区切りごとに「コード引用→解説」を繰り返す。目安: 1つのまとまりが数十行を超える、
   または複数の関数・責務が混在する場合は分割する。

3. **統計学・計量経済学的な解説を付加する**
   対象コードが推定手法のロジック（`engine/` `engine_pybind/` `python_package/`の統計計算部分、
   `benchmark/`のリファレンス実装呼び出し等）を含む場合、コードの構造説明だけでなく、
   それが数式・統計的概念として何を表すか（例: 残差平方和、共分散行列のサンドイッチ推定量、
   自由度調整の意味等）も併せて説明する。単なるデータ加工・configクラス等、統計的意味を
   持たないコードにはこの観点は無理に付け足さない。

4. **ファイル内の位置づけを示す**
   対象コードが他のファイル・呼び出し元とどう繋がっているか（`grep`で参照元・参照先を
   確認した上で）を示し、リポジトリ全体の中での役割が分かるようにする。

## 手順

1. **対象コードを読む**
   `Read`で対象ファイル・関数を読み込む。関連する呼び出し元・呼び出し先の把握が必要な場合は
   `Grep`/`Glob`で調査する（大規模・多数ファイルにまたがる場合は`Explore`エージェントに委譲し、
   メインセッションの文脈を汚さない）。

2. **区切りを決める**
   上記方針2に従い、解説の区切り単位を決める。

3. **区切りごとに解説する**
   区切りごとに、該当コードを示しながら以下を説明する。
   - 何をしているか（処理内容）
   - 使われている言語機能・構文の意味（初心者向け）
   - なぜそう書かれているか（設計判断・呼び出し元との関係）
   - （該当する場合）統計学・計量経済学的な意味

4. **気づいた点の一言報告**
   解説の過程で重複ロジック・デッドコード・不整合なコメント・非効率な実装等に気づいた場合は、
   解説の最後に対象（ファイル・行）と内容を簡潔に伝える。体系的な洗い出しや
   Issue起票はこのスキルでは行わず、希望があれば`/refactor-candidates`
   （洗い出し・起票）を案内する。修正は`/refactor`に委ねる。

## 完了条件

- 対象コードの全区切りについて解説を終えている
- 統計学・計量経済学的な意味を持つコードには、その説明が含まれている
- 気づいたリファクタリング候補があれば伝えている
  （無ければ「今回は無し」と明示してよい、報告漏れを避けるため無言で省略しない）

## 制約

- 対象コード自体は変更しない。
- Issueの起票・コメントはしない（`refactor-candidates`の範囲）。
- 統計的意味を持たないコードに無理に統計学的解説を付け足さない。
