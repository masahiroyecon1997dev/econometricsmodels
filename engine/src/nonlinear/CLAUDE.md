## 踏んだ罠（再発防止）

- **大標本Newtonの収束判定 `tol` は総和勾配に対する絶対しきい値で n スケールしない（Issue #291、修正済み）**: `common.rs` の `FaerNewton::terminate` の主判定は `l2_norm(gradient) < tol`（既定 `1e-6`）。勾配は n 個の観測スコアの総和なので収束点近傍で桁落ちが支配的になり、達成可能な勾配L2ノルムの「床」がデータ依存で `tol` を超える（`moderate_censoring` Tobit の実測で `n=200_000` は床≈`1·tol`、`n=1_000_000` は床≈`36·tol`）。この状態でコスト関数が浮動小数点の底（`|cost|≈1e5`, ULP≈`1.5e-11`）に達すると、`regularized_newton_step` の LM ラダー（`λ` を `0→1e-3→×4→…`）がどの `λ` でも `candidate_cost < cost`（狭義）を満たせず、**修正前は無条件で `Err(MleError::SingularHessian)` を返していた**（`ComputationError: the Hessian is singular and cannot be inverted`。実際には収束点の `-H` は良条件で、メッセージは誤り）。#284（Probit 大標本で Hessian 特異）と同系統。
  - **修正内容**: `regularized_newton_step` の戻り値を `RegularizedStep` enum にし、LM ラダー全失敗時に **`λ=0`（正則化前）の `newton_step` が可逆だったか**で分岐する。可逆なら `RegularizedStep::NoProgress`（真に特異ではなく、コストが底に達しただけ）、不可逆なら従来どおり `SingularHessian`（完全な多重共線性等、`run_solver_newton_returns_singular_hessian_error` の `SingularHessianProblem`）。`FaerNewton::next_iter` は `NoProgress` を受けたとき、次の3条件がそろえば `stalled_at_optimum` を立て、`terminate` がそれを見て `SolverConverged` を返す（現在点をそのまま返し、生ステップは適用しない）:
    1. 生の Newton ステップを1回進めても勾配ノルムが実質的に減らない（`≥ NEWTON_STALL_GRAD_RATIO=0.9 · 前反復`）
    2. 勾配ノルムが収束目標の近傍（`< NEWTON_STALL_GRAD_FACTOR=1e4 · tol`）。最適点から遠い停滞・発散を除外
    3. **コスト関数（負の対数尤度）の Hessian が正定値**（`cost_hessian_is_positive_definite`、`llt`）。`newton_step` の列ピボット QR は可逆性しか見ないため、鞍点（可逆だが不定符号。Tobit の `(β, logσ)` 尤度は大域凹でない）で `NoProgress` が返っても収束扱いにしない。3条件が揃わなければ生ステップを適用して反復継続 → `max_iter` 到達で `NonConvergence`。
  - **切り分けの決め手（調査時）**: 同一データで `tol` を `1e-5` 以上に緩める / `method="lbfgs"` にすると収束し、`observed_information_cov_params`（= `-H` の Cholesky 逆行列）も成功する。`cov_type="opg"` でも同じエラーが出る（opg 経路は `neg_hessian_inverse` を呼ばない）ことから、失敗は SE 計算ではなく最適化ループ内。
  - **Logit/Probit は挙動不変**: 尤度が大域凹で LM ラダー全失敗（`NoProgress`）に入らない。既存の `SingularHessian` テスト（完全な多重共線性）は `λ=0` の Hessian が不可逆なので従来の分岐に落ちる。engine 428 テスト・nonlinear pytest 421 テストが非リグレッションでパス。
  - **再現/検証データ**: `benchmark/nonlinear/datasets.py` の `generate_censored_regression_dataset("moderate_censoring", n, k=5, seed)`。`n=200_000 seed=1` は数値微分MLE（scipy BFGS）と logLik が `-204908.222939`（相対誤差 2.6e-13）で一致、`n=1_000_000 seed=42` も logLik 相対誤差 2.6e-13・σ 相対誤差 6e-9 で一致。Rust ユニットテストは `common.rs` の `run_solver_newton_converges_when_cost_hits_floating_point_floor_above_gradient_tol` / `..._stalled_at_optimum_reports_converged_even_without_raising` / `..._does_not_treat_flat_cost_with_large_gradient_as_converged`（条件2ガード）/ `..._does_not_treat_indefinite_hessian_stall_as_converged`（条件3=正定値ガード）。`FloatingPointFloorProblem` / `FlatCostLargeGradientProblem` / `IndefiniteHessianStallProblem` は機構とガードの模擬。
  - **残タスク**: (a) 大 n を凍結フィクスチャ化した pytest レグレッション（`testing-policy.md` のフィクスチャ方針）と `AER::tobit` クロスチェック。`FloatingPointFloorProblem` は機構の模擬であって「実 Tobit 経路が `NoProgress`→`stalled_at_optimum` を通る」ことは保証しないため優先度高。(b) `performance/compare_tobit.py` の `n_sweep` 上限（現在 100,000 に制限）見直し。(c) `NEWTON_STALL_GRAD_FACTOR` の絶対閾値依存を、スケール不変な Newton 減少量 `√(gᵀH⁻¹g)` ベースの停止基準に置き換える検討（rust-reviewer 指摘、スコープ超で保留。`docs/planning/specs/nonlinear-implementation-notes.md`）。
