# 仕様書整合ルール

## 基本ルール

- 実装の根拠は `doc/spec/` 以下の仕様書とする
- **仕様書にない変更・追加は実装前にユーザーに確認する**
- モジュールと仕様書は 1 対 1 で対応させる（例: `crates/ols/` ↔ `doc/spec/01_ols.md`）

## 実装前チェックリスト

1. 対象モジュールの仕様書 (`doc/spec/<module>.md`) を Read で確認済みか
2. 実装する数式・アルゴリズムが仕様書と一致しているか
3. 仕様書に記載のない挙動を追加していないか
4. API シグネチャ（引数名・型・戻り値）が仕様書と一致しているか

## 仕様変更が必要な場合

仕様書の変更が必要だと判断した場合は、実装より先に以下を行う:

1. 変更理由と影響範囲をユーザーに提示する
2. ユーザーの承認を得てから `doc/spec/` を更新する
3. 更新した仕様書を根拠として実装を進める
